Branch `ai/m19`, worktree `.worktrees/M19`, cut from `main` at `87e16dc`, merged with `main` at
`9d4da76`. Five commits, then a gap-fix: the merge and four more.
**Ready to verify. Not merged onto main, not pushed.**

## What landed

A block parser in `MCPRouterKit/Markdown/` producing typed blocks, with `AttributedString(markdown:)`
kept for the inline runs — the shape `spec-M19.md` §3.6 settles and tells the planner not to
re-open. On top of it: a shield parser that turns a badge URL into a key, a value and a tone; a
package image resolver; the `CapabilityDocument` types and a fixture package of real files; a view
per block kind in `MCPRouterUI/Document/`; the three-tab panel with its product header, its
five-cell facts strip and its capped scrolling body; and the surface's whole measurement apparatus
under M23.

The security work is the substance rather than the trimming, because the thing being rendered
arrives from a marketplace into an app that rewrites other tools' configuration. `MarkdownInline`
rebuilds the parser's output run by run against an allowlist — presentation intent, and a link only
where the scheme is `https` — so `imageURL` and anything a later toolchain adds to that scope are
gone by construction rather than by a removal list somebody has to remember to extend. `Shield` has
nowhere to put `#4c1`, which is the structural half of *the shield colours are the token values
rather than the badge's own*. `PackageImageResolver` refuses a scheme, an absolute path, an escape
and a symlink out of the package, each with its own sentence, and the resolved image reaches the
view as bytes so no view holds a path it could open.

## The one decision, and the lane that settled it

The router serves no document. Measured: `src/control.ts:279-283` admits `/servers`, `/usage` and
`/registry`, and no wire type — `RegistryEntry`, `Skill`, `PluginOrigin` — carries a read me, a
changelog, a licence or a capability table. So there is nothing observed for this panel to render,
`DESIGN.md` §6 forbids rendering what is not observed, and `spec-M19.md`'s own header gives the host
panel to M18.

Three options went out of family before the plan was written. `grok-4.6` refused with a 402 and
`codex` is recorded down to 2026-08-27; `agy` / `gemini-3.7-flash-high` answered and took the same
option I would have: ship the renderer, the panel and the measured surface, add no entry point.
It rejected a wired `Read me…` button as advertising a capability the router cannot supply, and
rejected the endpoint as a backend feature outside the triaged brief. Its refinement is taken —
name the contract in a protocol whose production arm returns unavailable, and file the endpoint as
its own item. Recorded in full at `planning/evidence/M19-review-agy.md`.

One thing the spec parked is unparked by measurement instead: M21 merged at `e121801` and
`ColorToken.shieldGood` exists, so the acceptance line the spec deferred is written here.

# Gap-fix — the two blockers, the four corrections, and one the verdict left optional

Verified **Needs More Work** at `54bb0aa`; the verdict is `planning/verification/M19-verdict.md` in
`.worktrees/M19V`. `main` merged at `9d4da76` giving `1e43252`, and every figure here was measured
on that tree rather than carried forward. The renderer was never in question — the verdict measured
the product separately and it holds. Everything below is the evidence.

## F1 · the guard that could not fail

`MarkdownBlock.plainText` was constructed nowhere in `app/`: the parser's fallthrough for a
construct it cannot type was `readParagraph`, so the kind was unreachable and
`CapabilityDocumentFixtureTests.nothingFallsBack` — the only guard on *no block falling back to raw
text*, half the brief's single acceptance line — passed for every possible input.

The verdict offered two closures and named deleting the case as the smaller. I took the other one,
because the smaller change contradicts the committed plan: `planning/plans/plan-M19.md:172-173`
specifies *ATX heading (1–3 hashes; four or more is `.plainText`)*, and `MarkdownBlock.swift:17` and
`MarkdownParser.swift`'s type comment both already described that behaviour. The implementation had
diverged from the plan and the documents were right; deleting the case would have made the documents
wrong to match the code.

`hashLine(_:)` replaces `heading(_:)` and returns three outcomes rather than an optional, because
the old function returned nil for two different reasons and only one of them is prose. `#hashtag` is
a paragraph; `#### deeper` is a construct with no role on `DESIGN.md`'s ladder. A fallback is a
block in its own right, so a paragraph run now stops at one instead of swallowing it.

Three controls, because an absence check cannot detect its own blindness:

| Control | What it holds | Where |
|---|---|---|
| presence | `#### deeper` parses to exactly one `.plainText` carrying its own source | `MarkdownParserTests.fourthLevelFallsBackVisibly` |
| presence, in the suite that does the counting | the same filter over a document that does fall back returns 1 | `CapabilityDocumentFixtureTests.theFallbackFilterCanReturnABlock` |
| negative | `#hashtag` and `####hashtag` stay paragraphs — a fallback firing on ordinary text would be worse than one that never fires | `MarkdownParserTests.hashtagIsNotAHeading` |

## F2 · the arm that reddened by crashing

A2 replaced `(1 ... 3)` with `(1 ... 0)` and the process died on `Fatal error: Range requires
lowerBound <= upperBound`. `m19-red-green.py` read the exit code, and a trapped process and a caught
defect are identical to an exit-code reader.

Four conditions now hold per arm, and each was a way the old file could report a guard as proven:

1. the named test runs at all — a filter selecting nothing exits 0, so every run asserts `1 test in
   1 suite`;
2. it **passes on the unmutated tree**, which is what makes the red mean the mutation;
3. the mutated run records an issue against that test **by name**, read out of the run's own output.
   Each arm runs its one test alone, because *the suite went red* is evidence that one property is
   covered and never that the suite covers the change;
4. nothing trapped, and nothing failed to compile.

A2's mutation is now `(1 ... 2)`: `### Flags worth knowing` in the fixture read me loses its role on
the ladder and falls back, which is the property the test names, reached by parsing. A9 is new and
guards the guard — it turns the only construction of `.plainText` back into a paragraph, which is
the state that made A2's assertion unfailable in the first place. The display names moved into the
table, so a renamed test is a red arm rather than a silent pass; A1's old row named a guard no test
was ever called.

```

```
