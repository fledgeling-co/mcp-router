# G8 — a question answered at the wrong scope returns a clean answer

**Branch:** `ai/l4` · **Base:** `main` at `49eae13` · **Spec:** `planning/specs/spec-G8.md` ·
**Plan:** `planning/plans/plan-G8.md` · **Evidence:** `planning/evidence/G8/scope-invariance.md`

## What was built

`planning/scope-invariance-gate.py`, in `make lint`. Two arms: a static one over every tracked
`.py` file, requiring a corpus-enumerating git subcommand (`ls-files`, `ls-tree`, `grep`) to be
anchored to a root the instrument derives rather than inherits; and a dynamic one that runs the
instruments named in `INVARIANT_RUNS` from the repository root and from `planning/` and requires
one answer. Eight controls run first on every invocation, and a run whose controls did not all
hold exits 4 and prints no verdict.

Three instruments were anchored: `planning/claim-sweep.py`, `planning/py39-annotation-gate.py` and
`planning/m33-branch-sweep.py`. Each now enumerates under a root derived from `__file__` and reads
every path back under that same root.

## The three instances, before the change

Measured at `49eae13`, root against `scripts/`:

| instrument | from the root | from `scripts/` |
|---|---|---|
| `claim-sweep.py` | 11 blocking hits, exit 1 | 0 hits, exit 0 |
| `py39-annotation-gate.py` | swept 77 files, `control: HELD` | swept 9 files, `control: HELD` |
| `m33-branch-sweep.py` | `examined=233 affected=7` | `examined=233 affected=0` |

The middle row is the reason this gate exists beside `sweep-control-gate.py` rather than inside it.
**A presence control proves an instrument is not blind. It does not prove it was pointed at the
right set** — the planted instance is inside the narrowed corpus by construction, so the control
held in the column that was wrong.

The third row is the same failure in a sweep whose subject is a denominator. Its header says the
number it must never print is a bare `affected=0` with no denominator beside it; from a
subdirectory it printed `affected=0` **with** one.

## What was left alone, and why

- The brief's other two scope items — M16's reduction in `mock_fidelity.py`'s header and
  `role-intersection-gate.py` — were already on `main`. This branch does not re-do them; the spec's
  §1 records where each landed.
- Shell is declined by the gate, counted and named rather than assumed empty. One file qualifies
  today and is anchored by a `cd`.
- `claim-sweep.py` is out of the per-run dynamic set on cost (~12s CPU per run). Its invariance is
  measured by hand in the evidence bundle and the decline is printed on every gate run.

## One thing found on the way that is not G8's

`sweep-control-gate.py` runs `planning/evidence/M31/arm-sweep.sh` as a declared control. That script
plants a defect into `design/mcp-router-console.html` and restores it with no `trap`, so an
interrupted run leaves the plant in the tree — and its own restore check cannot see it, because the
corrupted file becomes the next run's baseline. Observed once here and restored. Filed as
`planning/features-to-triage/a-control-that-plants-a-defect-leaves-it-there-if-it-is-killed.md`
rather than fixed on this branch.
