## The two the fleet wrote

Both were the same mistake — a citation with a real anchor sitting one connective away from the
grammar that reads it.

- `Makefile` cited `shells.sh` line 495 and then wrote *calls* before the phrase it relied on, and
  `calls` is not a connective the frame grammar follows. No tree was named at all. It should have
  carried the tree the reading was taken at and the line's own text: it now reads `shells.sh:495` at
  `ae845a1` reads `build_freshness_require Debug-iphonesimulator`, which classifies `RESOLVES`.
- `planning/progress/G6.md` cited `spec-F1.md` line 166 while arguing that the line *itself* is

  citation's job to make checkable, written in the form that cannot be checked. It now carries

  that same line, 280 lines earlier in the same record, was already framed — so the file disagreed
  with itself about its own discipline.

## The four that are not this gate's subject

Each is recorded in `planning/citation-gate.py` beside the line that excludes it, in the gate's own
vocabulary, so the reason travels with the exclusion rather than living here.

**`planning/tailings-2/*.json` — generated. The glob named a directory instead of a generator.**
`planning/tailings/*.json` was already excluded. `tailings-2/` is the same skill's second run over a
later commit window: schema 1 in both, and every one of the seven over-baseline citations is the
identical machine-written probe title, `"function body is empty: <path>:<line>"`. The first run's
exclusion and the second run's inclusion were one artifact answered two ways. Widened to
`planning/tailings*/*.json`, which also covers the third run already on disk untracked.

**`planning/test-campaign/evidence.html` — generated, and its counter invited the wrong fix.**
The page is built by `evidence-page.py` from `campaign.json`, `inventory.json`, `cases.json` and
`evidence/`, and every one of its 18 citations is a verbatim copy of a `why` or `note` string in
those registries — which this gate already excludes as generated. Regenerating the page on
2026-08-27 produced the same 18, one for one, so a hand-edit buys nothing that survives the next
run of the generator. That is the decisive half: a per-file counter on this artifact can only be
satisfied by editing a file that is overwritten. The right fix lives in the registry and this gate
cannot see it, which is the cost of the line and is stated there: **the campaign registries are
unguarded for bare citations.**

**`planning/rescue/campaign-stash-20260827/*.json` — frozen, which is a different reason and gets a
different word.** It is a byte-copy of a campaign registry taken from a dropped git stash, committed
at `cb1d7de` so five cases could not be lost a second time. It makes no claim a reader follows — the
live registry does, and that one is excluded above. And the exclusion is not a convenience: a rescue
copy is evidence *because* it is identical to what it rescued, so framing a citation inside one
would destroy the only property it has. There is no edit to this file that both satisfies the
ratchet and leaves it a rescue. Excluded through a new `FROZEN` tuple rather than through
`GENERATED`, and counted separately in the `N4` line, so the two reasons never blend into one number
nobody can question.
