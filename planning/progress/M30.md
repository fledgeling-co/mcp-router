## The three questions the triage named, answered

### 1 · Which facts cells does the router genuinely observe?

One of the mock's five. Recorded in `spec-M30.md` §2.1 with a justification each, in
`ControlDocument.swift`'s `facts` doc comment, and asserted by
`ControlDocumentRouteTests.factsAreObservedOnly`, which requires all four of `Version`, `Licence`,
`Runs in` and `Reads` to be **absent from the wire**.

- **Kind** — observed. The transport is in the router's own config and decides how the child is
  started. Served as `stdio` / `http` / `sse`, never as the fixture's `Skill · no server`: this
  router has no skills inventory and cannot know a capability is a skill.
- **Version** — not observed. No wire type carries one for an installed upstream; the manifest holds
  `builtAt` and a digest. Reading a `package.json` would be reading a convention the router does not
  otherwise use, about whatever happens to sit in `cwd`.
- **Licence** — not observed. The router can see that a `LICENSE` file exists; it cannot see that
  its contents are MIT, and `Licence · MIT` is the claim the cell would make.
- **Runs in** — not observed. `/harnesses` observes which harnesses point at *the router*. Nothing
  observes which harnesses could run *this capability*.
- **Reads** — not observed. Nothing observes what a child process reads.

Two cells are served **because they are observed rather than because the mock drew them**: `Tools`,
the length of the approved list this router connected and read, only when the manifest holds an
entry without an error; and `Served to`, the visibility restriction this router itself applies, only
when a non-empty `projects` list exists. A server with no manifest entry gets two cells.

### 2 · Do images travel as bytes?

Yes — base64 in the envelope, one entry per reference, with the media type. The response carries
**no package path at all**, asserted by `servesThePackagesFiles`, which fails if the root string
appears anywhere in the body.

Two consequences were built rather than assumed. The router needs its own image-reference scan,
because it decides which files to read — a router extracting a different set sends a different set
of bytes and the app cannot see it happened. And it needs its own resolution and refusal, which is
the traversal boundary. Both are ported to Swift and pinned by vectors.

The scan's one stated divergence from `MarkdownParser.inlineImages`: a run here is a maximal group
of non-blank lines outside a fenced block, joined with a space, which is coarser than the parser's
block breaks. It can over-approximate — costing bytes, drawing no wrong figure — and cannot
under-approximate, which is the direction that would lose a figure the app asks for.

### 3 · What is the transport cap?

Three, each named in its own refusal, all distinct from `MarkdownLimits` (which caps the parse, in
the app, after the bytes have crossed):

| Cap | Value | Refusal |
| --- | --- | --- |
| `documentBytes` | 524288 | `413 {reason: "documentTooLarge", cap, limit, actual, file}` |
| `imageBytes` | 2097152 | that image alone, `{reason: "tooLarge", limit}` |
| `imageBudgetBytes` | 8388608 | remaining images, `{reason: "budgetExhausted"}` |

An oversized image is refused on its own terms and does **not** spend the shared budget, so one
large figure cannot silently refuse every figure after it — pinned by the
`oversize-does-not-spend-the-budget` vector case, and by `imageOverTheCap`, which requires the small
image beside it to still arrive with its bytes.

## Changed vs the spec and the brief, disclosed

- **`RouterSheetTests`' unhosted-kind census moved from four to three.** `RouterSheet.Kind.readme`
  declared `owner == "M19"` — the marker for *drawn in the mock, hosted by nothing* — and hosting it
  is exactly what this item licenses, so no feature that closes M19's stated absence can leave that
  assertion standing. The replacement is strictly stronger: it asserts `readme` is hosted, carries
  no owner, and has a presentable case — three claims where there was one. This is the one test
  assertion this work changed, and it changed *with* the feature rather than to accommodate a
  failure.
- **`CapabilityDocument.Identity.publisher` and `.pitch` became optional**, and the header omits the
  row rather than drawing an empty one. The router observes neither for an installed upstream, and
  an empty `Text` in that stack reserves layout for a fact nobody has — the same §6 rule that keeps
  four cells off the facts strip. The fixture still supplies both, so M23's captured layer tree is
  unchanged.
- **`PackageImageResolver.Refusal` gained three cases** — `unsupportedType`, `tooLarge`,
  `budgetExhausted` — plus `unrecognised(reason:)` for a router newer than the app. Additive; the
  four existing cases and their sentences are untouched.
  `budgetExhausted` was reachable only through the caps vectors until 2026-08-27; it now has a route
  test of its own — `ControlDocumentRouteTests.imageBudgetExhausted` spends the real 8 MiB budget
  with four figures at the per-image cap and asserts the fifth is refused for the **budget** rather
  than for its own size.
- **`ControlHandler.reindexResponse` was extracted** from the dispatch switch. Adding the
  `/document` arm took the function to cyclomatic complexity 11 against a cap of 10; the reindex
  body carried two of the branch points and is a whole route rather than a fragment, so the seam is
  real rather than a way of paying for the new arm.
- **Three file-inventory censuses gained the new sheet file** — `SheetShortcutGuardTests.sheetViews`,
  `ShellTestSupport.boardFiles`, and a new `escapeFromHostedPanel` list. That last one is a
  **separate** dictionary from `noEscapePath` on purpose: `noEscapePath` is an allowlist of open
  defects, and `ServerDocumentSheet`'s Escape genuinely works — it hosts `CapabilityDocumentSheet`,
  whose `.onExitCommand` takes the key. The scanner reads one file at a time and cannot follow a
  wrapper into the view it renders. Collapsing the two lists would let a real gap hide among entries
  meaning "this is fine". The new list carries its own presence control: the panel it points at must
  itself be scanned and unexcused.
- **The `Payload` typealias on `ControlAPIClient`** exists because SwiftFormat wraps a longer
  signature and puts the brace on its own line while SwiftLint's `opening_brace` wants it on the
  signature's, and `.swiftlint.yml` reconciles those two only for wrapped statement conditions. A
  declaration long enough to wrap is a pair of gates nothing satisfies at once.
