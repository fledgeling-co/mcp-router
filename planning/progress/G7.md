## The measurement the item rests on, re-derived

`planning/progress/G5.md:159` at `a9603e5` reads:

> `installed_plugins.json` records **0.9.4** since 2026-08-21. The three gate scripts that matter are

At `0e5ff49` the file is 399 lines and `:159` reads:

> M28 docket and the X7 brief all name, and it reads what 0.9.4 reads on this data. What should move is

Two things beyond what the brief recorded. The sentence moved to `:170` at `43b44a2`, as the brief
says, but by `0e5ff49` **the anchor is not in the file at all** — `grep -n "installed_plugins.json\` records"`

about a different subject, which is the variety `M16` names as the one that gets believed.

## What was built

`planning/citation-gate.py`, run from `make lint`, plus `planning/citation-ratchet.json` and
`planning/practices/CITATIONS.md`.

The gate reads every `path:line` in the tracked corpus and sorts it into one of seven classes that
partition the set, so the column sums to the denominator and nothing falls out of the list.
`DRIFTED` (the anchor is in the file at that tree, at another line) and `ABSENT` (not there at all)
exit 1: a stated frame that does not hold is a false claim, where a bare citation is an absent one.
Bare citations cannot block, because there is nothing to compare them against; they are ratcheted
instead.

**Renumbering earns nothing from this gate**, which is the design constraint the brief set. A
number with no tree and no anchor stays `BARE` however recently it was chased, and `BARE` is the
class the ratchet holds down.

Both halves read whole files and collapse whitespace, per `planning/claim-sweep.py` — the half that
finds citations, and the half that looks for an anchor at a target line. An anchor's hit in the
collapsed view maps back to the line of its first character, which is how a wrap-tolerant reader
answers a line-anchored question.

### `N2 == N1` — withdrawn as a measurement, restated as an identity

This note read, and was wrong: *"`N2 == N1` says no citation in this corpus is split across a wrap
today. That is a measurement rather than an assumption only because the control proves the reader
would see one."* Both halves of that are false, and it is this item's own subject turned on itself —
a record asserting more than its evidence carries. It is withdrawn rather than deleted, because a
claim that was published and read has to be resolvable where it was read.

**Why it is an identity.** `normalise` replaces a run of whitespace with a single **space**, and
`CITATION` admits no space anywhere in a path or a line number. A citation a wrap has split
therefore reads `a.md: 2` in the collapsed view and is found by **neither** reader. N1 and N2 count
the same tokens by construction, and the printed `+0 vs N1` is a fact about the tokeniser rather
than a finding about this corpus. A fresh-context verifier settled it with a randomised differential
over 30,000 inputs carrying deliberate mid-token splits — **0 divergences** — and that differential
was re-run here against the delivered script with the same answer.

**The control cited as the warrant does not warrant it.** Its wrap row plants a hard-wrapped anchor
in the **target** file and requires the two readers to disagree about it. That is anchor matching,
which is a different question from tokenising a citation. And **none of the twelve planted rows
contained a newline at all**, so the citing side of a wrap was never exercised by anything.

**What would have to change for the two readers to differ.** Either `CITATION` admits whitespace —
`\s*` around the colon, say, so a split token matches — or `normalise` deletes a whitespace run
instead of replacing it with a space, so a split token closes up into one. Under either change
`N2 > N1` becomes possible and this line has to be earned again as a measurement rather than
inherited. Both facts are now held down by a control: a wrapped citation token must be found by
neither reader, and the unwrapped form of the same string must be found — so the identity fails
loudly on the run after it stops being one, instead of quietly staying in the record.

**What the collapsed reader does buy on the citing side.** The *frame*, not the token. `prefix` and
`suffix` are taken from the collapsed text, so an anchor phrase or a tree sha that a wrap separated
from its citation sits adjacent to it here, and the citation resolves. That is the citing-side wrap
worth having and nothing exercised it either; it is a control now, and it discriminates — the same
planted citation reads `RESOLVES` read whole and `TREE_ONLY` read a line at a time.

Classes over N5: `RESOLVES` 21, `DRIFTED` 0, `ABSENT` 0, `NOTREE` 1, `TREE_ONLY` 8,
`ANCHOR_ONLY` 113, **`BARE` 1291**. The ratchet baseline is that 1291, and the gate prints the ten
files carrying the most of them — `ORCHESTRATOR.md` 68, `LEDGER.md` 54, `R17-gapfix-3.md` 50 — so
the number is lowerable rather than merely held.

The gate held this note to its own rule while it was being written. A first draft cited
`claim-sweep.py`'s four pre-existing hits and the G5 line above without their frames; the ratchet
read 1294 against 1291 and exited 1. Those five carry frames now, rather than the baseline being
raised to accommodate them.

## Presence controls

**The fixture control** builds a throwaway git repository with two commits and runs the real
classifier over twelve planted citations, one per answer, on every invocation. Nothing is planted
in the corpus, because `G4`'s seventeenth item is a wrap control quoted unwrapped inside the
document it guards, where the naive matcher finds the quotation instead of the wrapped instance and
the control passes silently for the wrong reason.

Two of the twelve carry the load. The **wrapped anchor** must read `RESOLVES` here and be invisible
to a line-anchored reading of the same fixture; the run fails if those agree, because a
wrap-tolerant reader that would have answered the same either way has demonstrated nothing. It
prints both readings: `line [3] wrap-tolerant, — (invisible, as required) line-anchored`. The
**plausible** row must classify `ABSENT` with evidence reading `DANGEROUS`, against a
**citation into nothing** row that must read `announces itself`.

**Two checks run beside the twelve**, because all twelve are a single unwrapped line each and so
reach only the cited side of a wrap. A wrapped citation **token** must be found by neither reader
and its unwrapped form by both — that is what the `N2 == N1` identity above rests on, rather than on
the wrap row. A wrapped **frame**, the anchor sitting on the line above its citation, must read
`RESOLVES` whole and something other than `RESOLVES` a line at a time; it reads `TREE_ONLY` a line
at a time, so reading whole files is demonstrated on the citing side rather than assumed.

**The corpus control** planted three defects in `planning/progress/G5-gapfix-3.md`, each reverted to
a byte-identical file (sha256 `249fce21fd1e1f7d7a581127e5fbb5d3be72ed47c98cf9a7810e72096eb11221`
both ends):

## Two defects the controls found in the gate itself

**The dedup key hid a bad frame behind a good one.** Keyed on (citing file, cited path, cited
line), the wrong-tree plant was deduplicated away behind the correct citation of the same line in
the same file, and the gate stayed green on a planted defect. That is `G8`'s shape — a clean answer
to a narrower question — and it is why the second plant is in the record rather than only its
result. The frame is now part of the key, which moved N3 by +22 on the tree where it was measured (1666 to 1688).

**A first cut read frames by proximity and measured nothing.** Taking any backticked span within a
few hundred characters as a candidate anchor made 1163 citations look anchored and blocked 54, and
several of the blocks were the reader picking up an unrelated phrase from the same sentence. The
grammar is now adjacency-based, and both false positives are planted in the control so they cannot
return: a phrase two clauses from its citation reads as no anchor, and `` `X.md:159 at a9603e5` ``
— the whole frame inside one backtick span, which is how the `G7` brief itself writes it — is
`TREE_ONLY` rather than an anchor scraped off the clause behind the span's closing tick. The gate
blocked on the brief's own sentence before that was fixed.

The cost of the tight reading is stated in `CITATIONS.md` rather than hidden: a citation whose
anchor sits two clauses away is read as unanchored, and counted in the 1291.

## The out-of-family review, and the two things it changed

`agy` / `gemini-3.7-flash-high`, from `/tmp` with `--new-project`, bounded at 600s; the reply is
on-subject and ranked five gaps. Two of them changed the delivery.

**The ratchet was scalar, and a scalar ratchet leaks.** Holding a total lets a deletion or a
refactor in one file buy headroom for a brand-new bare citation in another, so the defect spreads
while the number holds. The baseline is now per citing file across 228 files, and each file's count
may only fall. Armed by an offsetting plant: one bare citation added to `planning/progress/G7.md`,
whose baseline is 0, and one existing citation framed in `planning/progress/G5-gapfix-3.md`, leaves
the total at **1291 against a baseline of 1291** — which a scalar ratchet passes — and the per-file
one exits 1 naming the file. Both files reverted byte-identically
(`7c8a09f1…` and `249fce21…`).

**The parser fallback was invisible.** A frame the adjacency grammar cannot follow lands in `BARE`
rather than in an error class, so an `M16`-form citation written with an unrecognised connective
drops past the blocking check silently. That cannot be closed without loosening the grammar, which
is what produced 54 false blocks on the first cut, so it is measured instead: every run prints how
many `BARE` citations sit within reach of a SHA-shaped token. **82 of the 1291.**

Three findings are not acted on. Two — the 113 `ANCHOR_ONLY` pinned to `HEAD`, and `make lint`'s
placement being unproven here — the delivery already declared and are below. The third says
repointing ten citations while leaving 1291 means the gate substituted for the sweep. The count is
right and the reading is half right: the sweep is what produced the 1291, and the two largest
holders are `ORCHESTRATOR.md` at 68 and `planning/features-to-triage/LEDGER.md` at 54, which this
run was forbidden to write. What is left is 122 citations in two files a later pass owns, and 1169
in 226 others.

## Open

The 1291 bare citations are held, not fixed. Repointing them is not one item's work, and the
ratchet is the mechanism for working the number down; `--write-ratchet` lowers the baseline in the
same change that repoints.

`ANCHOR_ONLY` at 113 is checked against `HEAD`, which is a moving frame, so those pass today and
say nothing about tomorrow. They are the cheapest class to convert: they already carry the phrase
and need only the tree.

The gate reads Python, Markdown and the other tracked text formats through one regex over file
extensions. A citation written in a form the adjacency grammar does not parse is counted as `BARE`
rather than reported as unparsed, so the 1291 is a ceiling on unfalsifiable citations and not an
exact count of them; 82 of them carry a SHA-shaped token nearby and are the likeliest to be frames
the grammar missed rather than citations nobody framed.

# G7, third axis — a citation that IS in the repository and still names nothing

Delivered on `ai/g7` from `1cf88b9`, 2026-08-27. The first half of this item asked whether a
**frame** holds. This half asks whether the **target** exists — and the two are independent, which
is the whole reason there is a second half. A citation can be committed, repo-rooted, and carry a
perfect anchor and tree, and still point at a file that moved, a file that was deleted, or an id
that was renumbered underneath it.

## The census, which is the finding

Three citation forms, three questions, none of them blended into the others. Measured over the
tracked corpus at `1cf88b9`.

| form | population | the question | who reads it |
| --- | --- | --- | --- |
| `path:line` | 1532 checkable | does the pinned line still hold the phrase relied on | `citation-gate.py` |
| a repo-rooted path | 1651 | does the target exist at all | this gate |
| a registry id | 1057 | does the id still name a row | this gate |

**Resolving.** 648 of the `path:line` set resolve against a stated frame; 1596 path targets resolve
at the index; 963 ids name a row.

**Not resolving, split by cause — the three the brief asked for:**

- **Line pins that shifted: 0, and the 0 is a floor rather than a finding.** `citation-gate` reports
  `DRIFTED 0` and `ABSENT 0`, but 723 of its 1532 are `BARE` and 161 more carry only one coordinate.
  **883 of 1532 cannot be asked the question at all**, so "no line pin has drifted" is a statement
  about the 648 that carry a frame and about nothing else. That is the honest shape of this number
  and it is why the bare ratchet matters more than the drifted count.
- **Ids renumbered: 0 today, and the reason is checked rather than hoped for.** `G16` became
  `DEF-059`, `G19` `SURF-027` and `G17` `CASE-0184..0194` on 2026-08-27, and all three are silent
  because the old ledger rows were kept and the new campaign rows added, so both ids resolve. One
  id has no row anywhere — the one `X7`'s brief names because it is absent — and it classes
  `ID_WITHDRAWN` rather than blocking, for the reason below.
- **Targets moved or deleted: 22, in 16 citing files.** 13 `PHANTOM` (in no commit reachable from
  any ref) and 9 `DELETED` (gone, no frame, no marker). 0 `MOVED`, because nothing in this backlog
  was renamed with a rename git recorded — the class is reachable, and a planted `git mv` reaches
  it and names the successor.

## The gate blocked its own census, twice, and that is the finding under the finding

This record cannot be written without naming pointers that do not resolve. The first draft named
an absent id to report it and the id arm blocked the sentence; the second named two phantom
evidence artifacts and the path arm blocked those, because `foreign-path-gate`'s marker is read
only *after* the path and a record listing dead pointers writes the marker *ahead* of them.

A gate that forbids its own findings from being written is a gate that gets softened, so both arms
now read a marker in the citation's own **sentence**, either side of it, with a negative control
holding the boundary: a marker across a full stop is about some other pointer. That widening was
measured before it was trusted — it moved exactly the two sentences it was for and excused none of
the 22 in the backlog.

`PHANTOM` is the class worth having, and it is not the class the brief predicted. A `DELETED`
citation rotted: there is a tree where it was true, and carrying that tree repairs it. A `PHANTOM`
citation was **never** true anywhere, so no frame can repair it — the remedy is to commit the
artifact or withdraw the claim. Three of the thirteen name an artifact a record calls **evidence**
and no commit holds: `planning/fidelity/dumps/servers.ideal.json` in `M16`'s and `M23`'s acceptance
records, and `planning/progress/M29-gapfix.md` in `G6`'s. That is `G24`'s defect outside the
campaign directory, which is where `evidence-citation-gate` stops looking.
