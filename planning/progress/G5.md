### The boundary, and why it is narrower than the one the verdict validated

The verdict validated `(?<![A-Za-z0-9])installed(?![A-Za-z0-9])` and measured it raising `role`
825 → 872. That form treats every underscore as a separator, so it also reads the word inside
`installed_plugins`, `board_registry_installed_count` and `INSTALLED_COUNT` as a use of the word —
which is `V6`'s defect moved into the instrument.

The shipped boundary separates on an underscore run only when the run has no letter or digit on its
far side, which is what distinguishes markdown emphasis from an identifier. Measured on a clean
checkout of `6a3dbb8`, over distinct `(file, line)` sites:

| boundary | `role` hits | distinct sites | what moves |
|---|---|---|---|
| `\b`, as delivered | 825 | 788 | — |
| shipped at gap-fix 5 | 826 | 789 | one site: `G5-gapfix.md:24` |
| the naive widening | 872 | 823 | 34 further sites, every one an identifier |

The 34 tokenise to `installed_plugins` (18 sites), `INSTALLED_COUNT` (9), `board_registry_installed`
(5), `installedAt` (3), `board_registry_installed_count` (3), `INSTALLED_NAMES` (3) and
`INSTALLED_LIST` (1); no site among the 34 lacks an underscore-joined identifier. Normaliser: the
guard run from a fresh `git clone --no-hardlinks` checked out at `6a3dbb8` and `git clean -qfdx`,
once per boundary, differenced on the set of `(file, line)` pairs.

**The set, and not the printed rows — I got that wrong first.** The guard prints `role` as one line
per file with the line numbers listed on it, so `diff` over two runs reports the whole file row as
changed when a single number inside it moves. Read that way, the naive boundary looked like it added
seventeen whole files, one of them thirty-three sites wide, and the shipped boundary looked like it
added a file it had only lengthened by one entry. Parsing both outputs into `(file, line)` sets gives
the table above: one site added by the shipped boundary, thirty-four more by the naive one. Recorded
because a diff of a grouped report reads as a measurement and is not one — the same shape as the
denominator this pass is here to correct.

`blocking` is 0 under all three, so no live binding was hidden by the escape. And `13 → 0` survives
the change of instrument: against a clean checkout of `43b44a2`, the guard as it stood at `6a3dbb8`
and the gap-fix 5 guard both read `blocking 13 · record 15 · nonprose 2 · role 794`, because the
emphasis form did not enter the corpus until `f5a1ab9`.

Each half of the boundary is proved by a mutation that reddens it and nothing else. Restoring `\b`
fails 8 selftest rows — the three emphasis runs under `BOUNDARY`, and five defect samples across
`I1`, `I2` and `T1`. Substituting the naive widening fails 4 — the four identifier rows under
`BOUNDARY`, and nothing else, because the block patterns cannot carry that half: `CONN` stops at
`count` before a version is reached, so an identifier sample stays clean under a boundary that is
wrong. That is why `BOUNDARY` exists as its own list rather than as more `SELFTEST_CLEAN` rows.
