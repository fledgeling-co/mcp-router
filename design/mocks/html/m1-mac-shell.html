M1 — Mac window shell, menu bar, keyboard

The container every other Mac surface renders into: a 33pt titlebar, a 52pt unified toolbar, a 256pt sidebar with inset-rounded selection, the complete menu bar, the keyboard map from DESIGN.md §8, the scroll-edge effect and window restoration. The boards that fill the content zone belong to M2–M8; what is specified here is what they render into and the nine states the shell itself has to answer for.

1The window, populated

The three zones, at size. The sidebar carries two groups in sentence case and one ungrouped destination; the badge on Servers is the number of servers wanting a human decision, which the router reports per server (pendingChange, an unauthorised OAuth upstream, or an indexError). The badge on Cleanup is the number never called. Both are counts the router observes. Skills and Inbox carry no badge, because the control API exposes no skills and no inbox endpoint and a count there would be invented.

2The complete menu bar

§3.9 makes the menu bar the complete command surface: every command is reachable from it. Every ⌘-shortcut in DESIGN.md §8 is a menu item here, because a ⌘-shortcut with no menu item is undiscoverable. Space, Return and Esc are deliberately absent — they are view-level keys on a focused row, a default action and a sheet, and macOS does not put them in menus (Finder binds Space to Quick Look and lists "Quick Look ⌘Y"). Commands whose surface is not yet installed dim in place with their reason in a help tag; they never disappear (§3.4).

Unresolved, recorded rather than guessed. §8 binds Space to "the selected row's breaker", but the control API has no start and no stop: ServerPatch is projects · warm · idleMs · placard, and ControlAPIClient carries no lifecycle operation at all. The breaker is a readout of a child process the router starts when an agent calls a tool. Either Space toggles warm — keep it resident versus let the reaper close it, which is a different sentence from the one §8 writes — or the router needs an operation it does not have. M3 owns the breaker and inherits the decision.

4The nine states

The shell's own data surface is the sidebar's counts and the at-rest readout. Every state below is one the fixture client can actually produce, so each is renderable without a router running. The navigation itself never goes away — a router that is not running does not stop you moving between destinations, and hiding the sidebar in a failure state would strand you on whichever pane you were looking at.

5The scroll-edge effect

Where content meets the toolbar. At rest there is no separator and the toolbar sits on the same ground as the content; the moment content passes under it, a --line hairline appears. This is what stops the toolbar floating free of a scrolled list, and it is the one piece of chrome that changes as you scroll.

6Window state restoration

Three things survive a quit, and each is restored by the mechanism that owns it rather than by one home-made store.

WhatRestored byWhy
Window frameAppKit frame autosave Position and size, per screen configuration. AppKit already handles a display being unplugged between launches; a hand-rolled store does not.
Selected destinationScene storage Per scene, so a second window keeps its own. Restores to Activity when the stored value names a destination this build no longer has, rather than showing a blank pane.
Sidebar visibilityScene storage Collapsed stays collapsed. The ⌃⌘S command and the restored value read the same state, so they cannot disagree.

Deliberately not restored: the scroll position of a board the shell does not own, and any transient failure state. Restoring an error from the last launch would show a condition that may no longer be true.

7Light appearance

Authored, never an inversion. Every dark indicator hue placed unchanged on the light ground lands between 1.71:1 and 2.91:1 against the 4.5:1 a label needs, so all four are re-solved in OKLCH; the tiers and lines reproduce dark's measured ratio rather than its alpha. The shell reads the same in both because the hierarchy is the same, not because the values are.

8Motion

Transform and opacity only, springs rather than durations, interruptible, and never an entry that animates opacity from zero. Reduce Motion removes the animation and never the state change.
