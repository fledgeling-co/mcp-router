## The defect diagnosed

`planning/foreign-path-gate.py` evaluates whether hand-written records cite scratch paths (`/tmp`, `$TMPDIR`, etc.) without recording what became of them.

At commit `597236c`, running the gate on the same machine yielded two different verdicts:
- Pristine detached checkout of `597236c`: **Exit 1 (FAIL)**
- Main checkout with uncommitted working-tree changes: **Exit 0 (PASS)**

### The mechanisms

1. **Enumerating from the index and reading from the disk**: `git ls-files` was used to list tracked paths, but files were opened directly from the working-tree filesystem (`read_text()`). An uncommitted edit marking a citation `(gone)` on disk changed the gate's verdict for a commit that did not yet contain that marker.
2. **Machine-local `/tmp` probing in the partition**: `exists_now()` checked `os.path.exists()` / `glob.glob()` against the runner's current host filesystem to split `CITED_LIVE` vs `CITED_DEAD`. This caused partition tallies to drift across runners, CI environments, and machine reboots.

## Corpus and Partition Specification

1. **Corpus of Record**:
   - Default: committed git tree at `HEAD` (or `--rev <rev>`), read directly as blobs via `git cat-file --batch`.
   - `--worktree`: inspects working-tree files on disk, announcing uncommitted changes if dirty.
2. **Deterministic Partition**:
   - Classes over N3: `RUNTIME`, `GENERATED`, `SUBJECT`, `CITED` (blocking), `WITHDRAWN`.
   - Host filesystem resolution (`live on host` / `dead on host`) is reported informatively in findings and summaries, without affecting partition totals or exit codes.
3. **Controls**:
   - 17 presence plants covering all classes, wrap discrimination, severity deduplication, generated file globs, host probe, and the G11 2-way checkout control (dirty working tree vs pristine clone).
