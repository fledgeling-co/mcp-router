# P9 — regenerating the vectors changed one, and the change went to the reference

`make parity-regen` was repaired so it can run. Running it did what the brief said it might:
**it disagreed with a committed vector.** The brief's own instruction is that this is the
finding: it says a regeneration which changes a committed vector *is* the finding rather than a
nuisance, because it would mean a recorded expectation had drifted from the reference and nothing
had noticed. Anchor `A regeneration that changes a`,
`planning/features-to-triage/parity-regen-is-broken-so-nothing-checks-the-committed-vectors.md:58`
at `c860ca2` (the sentence wraps, so the anchor is its first line). It was resolved correctly and then recorded only as a bullet in a commit message,
which is the half this file exists to repair.

## What diverged

The `failure-destroys-approved-tools` case of `build-manifest.json`
(anchor `"id": "failure-destroys-approved-tools"`,
`app/Tests/RouterCoreTests/Vectors/build-manifest.json:118` at `8013e73`).

The vector expects a server that fails to index to keep the `digest` it already had, alongside
the emptied `tools` array and the new `error`. The TypeScript reference did not emit it: the
`'error' in observation` branch built a fresh entry while the previous one was in scope, so the
digest went out with the tools.

## Which side was wrong, and why the reference was the one that moved

Two implementations disagreed and only one of them could stay. The vector was kept and the
reference changed, on three grounds that all point the same way.

**The Swift port already behaves the way the vector says.** Anchor
`if let prevDigest = previous?.digest`,
`app/Sources/RouterCore/Manifest/ManifestBookkeeping.swift:43` at `c860ca2`, under a comment at
`:35` reading `// R18: Preserve the previous digest across failure so that subsequent`. So the
disagreement was never Swift-versus-vector; it was TypeScript-versus-both.

**That behaviour is ratified, not incidental.** It is item R18 — anchor
`A failed index drops the digest, so the next success serves a changed surface unheld`,
`planning/features-to-triage/LEDGER.md:119` at `c860ca2` — filed as
`R18-a-failed-index-drops-the-digest-that-holds-the-diff.md`, taken to **Done** and merged at
`c6dd377`. R18 read the TypeScript drop as **incidental rather than deliberate**, on this
repo's own convention that every deliberate retention in that file carries a defending comment
and this branch had none.

**The consequence is a security one, which is why the vector wins a tie it would otherwise
lose.** The digest is what holds a changed tool surface for acceptance. Drop it on failure and
the entry looks like a server never seen before; the next successful index then takes the
first-sight branch, which approves whatever it finds. A failure followed by a success becomes a
route to serving a changed tool surface **unheld** — the auto-approval R18's title names. A
vector encoding the safe behaviour is therefore the artefact to preserve, and an implementation
that quietly drops a security hold is the artefact to correct.

The change is one spread, anchor `...(prev?.digest ? { digest: prev.digest } : {})`,
`src/manifest.ts:216` at `8013e73`, with `const prev` hoisted above the error branch at `:210`
so it is in scope there. An absent digest keeps meaning *never seen*, which is what the
held-diff branch at `:231` already assumes.

## What this vector is now the only coverage of

**There is no TypeScript test suite in this repo.** `package.json` has no `test` script and no
test runner among its dependencies; there is no `test/` or `tests/` directory and no `*.test.ts`
outside `node_modules`. Verified by inspection at `8013e73`.

So the coverage of `applyObservation`'s digest retention is exactly this, and nothing else:

| Rung | Artefact | Covers |
| --- | --- | --- |
| Swift unit test | `app/Tests/RouterCoreTests/ManifestDigestHoldTests.swift:46` at `8013e73` — anchor `#expect(step2.entry.digest == initialDigest, "R18: previous digest must be preserved across failure")` | the **Swift** implementation only |
| Parity vector | `build-manifest.json` case `failure-destroys-approved-tools` | the **TypeScript** reference, via `make parity-regen` |

The Swift test cannot fail on a TypeScript regression, and there is no other check that can.
Delete or edit that vector case and the TypeScript reference may drop the digest again with
nothing red anywhere in the repo. `make parity-regen` is out of `make all` because it needs node
and a built `dist/`, so the guard is real but it is also the quiet kind — which is the condition
the brief already named as the reason this item existed.

## The residual

The reference's digest retention has no test that runs without a built `dist/` and a node
toolchain. A TypeScript unit suite is out of scope for P9 — the item is about the regeneration
path, and standing one up is a repo-level decision rather than a gap-fix. Recorded here as a
known thin spot rather than closed.
