## What was built

**The band.** `SignalPath.swift` draws a head — title, topology line, four-swatch legend — over a
rail of hub → arrow → jack field. `Jack.swift` draws one jack; `StatePlug.swift` draws the mark it
leads with, at the two sizes the legend, the jack, the table row and the inspector take it.

**The field packs rather than grows.** `LazyVGrid` with `GridItem(.adaptive(minimum: 132))`, the
direct translation of `repeat(auto-fill, minmax(132px, 1fr))`. Measured at 1280×820: four columns,
track pitch 140 = 132 + the grid unit, field width 1112 — which is exactly what
`SignalPathGeometry.jackFieldWidth(inBoardWidth:)` predicts.

**The geometry is a value type with invariants, not literals in a view.** `SignalPathGeometry`
replaces `BreakerGeometry` one for one — same `documentedValues` contract, same parity suite, same
argument for living in the headless target. Ten rows in a new `### Signal Path geometry` table.
`columns(inJackFieldWidth:)` is the CSS `auto-fill` arithmetic written out, which is what turns the
brief's *"two jacks fit beside an open inspector"* from prose into an assertion.

**The presentation layer is one chain.** `JackState` inherits `BreakerState`'s ordering unchanged —
running first, because the plug's meaning is the lever's — with `wantsYou` split into `held` and
`needsSignIn` because a jack carries a word as well as a colour.

**The retirement.** `Breaker.swift`, `BreakerGeometry.swift`, `BreakerState`, the nineteen-row
table, `BreakerGeometryTests`, `BreakerGeometryParityTests`, and the breaker's rows in `DESIGN.md`
§1, §7 and §8. Three consumers were re-homed rather than deleted, because each carried an argument
that outlived the element: the badge bump, the loading skeleton, and A7's cross product.

**The gate.** `VOUCHED_CONTROLS` gains `jack` and `signature`; `servers.pairing.tsv` gains the band
and four jacks.

## The plan's out-of-family review, and what it changed

`agy` / `gemini-3.7-flash-high` reviewed the plan adversarially over eight questions and returned
**AMEND** with four rejections. `codex` is down until 2026-08-27 and `grok`'s balance was
re-confirmed exhausted on 2026-08-22, so the Google lane is the gate rather than a downgrade.

Two rejections changed shipped behaviour and both were real:

1. **A warm running server would have drawn a countdown.** The first draft computed the jack's word
   from the same chain as its plug. `ServerSubtitle` has put `warm` above `running` since M3 because
   the reaper skips a warm server, so the band would have read `3:41 left` while the hub two inches
   above read `1 at rest` — two statements about one server on one board. The word is now computed
   from the state **plus** `warm`.
2. **`at rest` counted the warm flag rather than warm children.** `warmUp()` logs and swallows a
   start failure, so a warm server that never came up carries `warm == true` while its process is
   not on the machine. It is `warm && state == .running` now.

The other two were a slice boundary that would not have compiled — B renamed `ServerRowModel.breaker`
while `ServersBoardRow.swift:46` still read it — and a vouch in `mock_fidelity.py` that would have
turned the build's own row plugs into findings by destroying the `covered-by-pair` exemption.

## Deviations from the plan, and why

1. **`SignalPathGeometry` rather than nine `MetricToken` cases**, against the spec's disposition
   that the literals *"route through `MetricToken`"*. They route through a token layer; which one is
   settled by `DesignDocParser.swift:327`, which records why the breaker's nineteen rows were kept
   out of the chrome ladder — *"mixing nineteen breaker rows into the chrome ladder would bury the
   four values a window actually lays out with."* `MetricToken.jackLane` stays where it is and the
   geometry reads it, so the lane is authored once and a parity test asserts it.
2. **`DesignDocParser.swift` was split.** Adding the Signal Path's reader took it to 410 lines
   against a 400-line limit, so the increased-contrast reader moved to a file of its own. That seam
   was already declared and already argued for in the comment above it. `tableLines` widened from
   `private` to internal as a consequence, which is noted at the declaration.
3. **`StatePlug` sits at `MCPRouterUI/` root rather than under `Boards/`**, where `Breaker.swift`
   sat and for the same reason: `StateContainer.swift` draws it and compiles for both platforms.
4. **The row's leading slot is the plug's width, so the table's columns moved left by 22pt.** That
   is the visible consequence of retiring a 30pt lever rather than an incidental change, and the
   column headers read the same value so the two cannot drift.
5. **AC9 was mis-specified and is recorded as not met.** It asked for the breadth finding count to
   fall; it is 116 before and after. `divergent` is a finding too, so an affordance moving from
   *not built* to *built and measured* trades one finding for another — and no fixture this build
   ships can make a jack's label equal the mock's eleven server names. What moved is the
   composition: `absent` 80 → 75, `divergent` 16 → 21, `covered-by-pair` 16 → 24, `extra` back to
   its pre-existing 10.

## What is open

- **The harness column is not built, and it is the one part of the brief this item does not
  deliver.** Its three states are `HarnessState` in `RouterCore/Discovery/HarnessReconciliation.swift`
  — `notWired(overlapping:)`, `wiredViaHTTP`, `wiredViaShim(bridge:)`,
  `wiredWithDuplicates(route:count:)`, the brief's three exactly — in a target neither app links,
  derived from harness config files. The control API serves no harness route; A36 forbids a board
  going round it. The one thing the app can see, the `client` on a call record, cannot produce *not
  routed* at all, because a harness that has never called cannot appear in a usage log — so the
  state carrying the finding is the state that reading cannot reach. **M22 absorbs `R7-C1` and the
  route**, and the column lands with it. Recorded in `DESIGN.md` §10 and in the pairing file's
  citations. The rail reads hub → jacks meanwhile, which is honest and incomplete rather than
  either alone. *(`spec-M22.md`:153 spells these cases `.wired(route:)`; the source is what is
  quoted here.)*
- **The band's own paragraph failed A36 before it passed it.** The first draft of `SignalPath`'s doc
  comment spelled out the file-reading APIs while explaining why this view may not use them, and
  that gate is a source grep that cannot tell a mention from a call. The prose is reworded and says
  so. Relaxing the grep to skip comments would put every forbidden call one `//` away from
  invisible — worth someone deciding deliberately rather than the next runner hitting it and
  reaching for the gate.
- **The last jack measures 142.5pt against its siblings' 132.** SwiftUI's `.adaptive` gives the last
  item in a row the remainder of its computed track set, where CSS `auto-fill` would leave empty
  tracks. It is inside the specification rather than outside it — `minmax(132px, 1fr)` allows a
  track to grow, and 132 is documented as a minimum — but it is a divergence from the mock's
  behaviour and is recorded rather than absorbed.
- **The eleven-upstream case is predicted, not measured.** The recorded fixture declares four
  servers, so the packing behaviour at the count the brief actually measured — eleven, which ran the
  band 500pt deep as a single column — is covered by `columns(inJackFieldWidth:)`'s arithmetic and
  by the observed 140pt track pitch, not by a render. A fixture with eleven servers would settle it.
- **`indicator` is unvouched in `mock_fidelity.py`, so 16 mock row-plug affordances still read
  `absent` while the build draws the mark.** The citation on each says why: the harness records no
  text for a dot, so a pairing fails `readable()` on both sides and lands `unclassified` — the
  gate's own phrase for agreement between two absences — and vouching the kind would additionally
  reclassify the build's own plugs as `extra`. It is `D-m23-h`'s subject, the mock kinds
  `VOUCHED_CONTROLS` does not name, and it wants an instrument rather than a table edit.
- **`DESIGN.md` §2's `Servers row` keeps 56pt with its derivation gone.** It read
  `56pt (4 + 48 breaker housing + 4)`; the housing retired and the value did not, because the
  table's conversion is another item's and a row height changed here would move the skeleton, the
  column headers and the inspector's neighbour. §10 records the mock's 36pt as owed.
