Spec `planning/specs/spec-F7.md` · plan `planning/plans/plan-F7.md`.

## What moved

`PRD.md` §6 has specified a session analyst since the PRD was written, and until this branch
nothing under `app/Sources` implemented one. Three surfaces said so in their own comments:
`ControlInsights.swift` wrote `analyst: null`, `InsightsBoard` drew an empty state with
`Button(InsightsBoardCopy.analyseNow) {}`, and `FindingArrival.swift` recorded that **no banner of
its family can fire in a shipped build, because there is no producer.** This item is the producer.

- **`app/Sources/RouterCore/Analyst/`** — eight new files. `SessionCorpusReader` reads the four
  JSONL session stores through `FileSystem` and reports per store what it parsed, what it discarded
  and, for a store it did not open, why. `SessionPatterns` counts recurring command heads and
  `command not found` signatures against a floor. `CLIAnalystJudge` runs the configured CLI through
  `AnalystProcessRunner` — argument vector, no shell, `stdin` closed, `PATH` resolved by hand so an
  absent binary is an absence rather than an exit 127. `AnalystPrompt.read` keeps only replies that
  name **both** an entry from the router's candidate list and a signal the run counted.
  `AnalystEngine` runs the ladder, rejects and counts what it discards, suppresses a fingerprint for
  thirty days, and persists.
- **Three control arms.** `analyst` on `GET /insights` — null for a router with no analyst, an
  object with a null `ranAt` for one that has not run. `POST /insights/analyse`.
  `PATCH /insights/analyst`. `ControlDeps.analyst` is optional and absent answers 503 naming the
  missing capability, matching `extensions`, `caches` and `health`.
- **The Insights analyst card.** The design's four readouts, three of them menus, replacing the
  empty state. Wired to the model, which posts and then **re-reads** `GET /insights`.

## Two things a verifier should not have to find

1. **`swift build` needs `--disable-sandbox` on this machine.** SwiftPM's own sandbox refuses to
   create build outputs on the volume the worktrees sit on, and it surfaces as
   `Operation not permitted` on a randomly chosen `.o` — never the same file twice. `make test`
   works once a build exists. The Makefile is unchanged; this is an environment fact, recorded
   because it reads exactly like a corrupt tree.
2. **The Insights fidelity ledger is now stale, and deliberately not regenerated here.**
   `planning/fidelity/insights.*` was derived against a build whose analyst card was an empty
   state. This item makes the build draw the card the mock draws, which moves the surface *toward*
   the mock — so the ledger's analyst rows need re-deriving from `make mock-fidelity
   SURFACE=insights` rather than editing. Owed, and named rather than left to be discovered.

## Found by arming, and fixed

`F7-A2` — dropping Cursor from the store table — first read **MISS**. The store-count assertion
compared the reader's output against `SessionStores.table(...).count`, which is the same expression
the mutation edits: both sides moved together and the assertion could never have failed. Corrected
to a literal five, asserted in both directions, and the arm then killed it.

`F7-A10` also exposed a hazard in the arming script itself. Its mutation deletes the analyst
dispatch line, which returns `ControlHandler.swift` to **exactly its committed content** — so when
the restore write hit this volume's intermittent `EPERM`, the branch silently lost that line while
`git status` reported the file clean. The script now reads the file back after restoring and exits
2 if it differs.

And `F7-A10`'s expectation list originally named the reachability case. It read MISS and was right
to: `A9` asserts that the two paths are **claimed** — 401 before 405, a neighbouring path unowned —
and every one of those holds with the dispatch arm deleted. Claiming and routing are different
properties, and only `A4` sees the second.
