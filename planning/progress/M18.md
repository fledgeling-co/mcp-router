**One enum, nested per host.** `RouterSheet` in `MCPRouterKit/Shell/` replaces five per-board
`Sheet` enums and two `Bool`-shaped presentations. Each board types its `sheet` as its own nested
group, so `inboxBoard.sheet = .addServer` does not compile rather than rendering something at
runtime. `RouterSheet.Kind` is the flat inventory — sixteen: the mock's thirteen plus the three the
build draws and the mock does not.

**The gate table is routed through, not merely declared.** `SheetGate` carries the brief's seven
rows plus `resetCallHistory`, and each board model gained `request(_:)`. The destructive call sites
ask for the *action*; the table decides the friction. That was the plan review's sharpest finding —
as first planned the table was a lookup nobody consulted, and its tests would have passed at full
green while a button called `remove(name)` directly.

**All seven `.sheet(` sites use `item:`.** The three that were `isPresented:` kept their by-id
lookup: `InboxBoardModel.sheet` and `DiscoverBoardModel.sheet` are **computed** from the existing
`sheetItemID` / `sheetEntryID` storage rather than stored beside it, so there is still exactly one
place each answer lives. A captured value would have satisfied the brief's letter and reintroduced
the stale-subject bug both models carry a comment about closing.

**`EvalsBoardModel.Sheet` deleted.** `recheckAll` was never assigned and never presented, and
`EvalsBoard` has no `.sheet(` at all, so `escape()`'s first arm was unreachable too. Both went.

**Two sheets the build did not have**, and both are honest about what they cannot say — see
*What could not be drawn*.

**Destructive is a role.** `StandardButtonStyle` reads `configuration.role`; four call sites
stopped naming a colour. The token moved with it, and that part is a measured fix rather than a
tidy-up: `ColorToken.fail.contrastRole` is `pairedWithAWord` while `failInk` is `text`, and these
labels sit on `--raised`, one of `DESIGN.md` §2's four text grounds. Every one of those four was
shipping a label in the indicator hue on a text ground.

## What could not be drawn, and why

Three things the mock draws are not in the build, each measured rather than assumed.

1. **`path` ships as a refusal.** The router computes the search path it hands its children
   (`src/pool.ts:168`, `augmentPath`) and publishes it nowhere: `ControlAPIClient` declares
   nineteen methods and none returns a path or an environment. Reading *this app's* login-shell
   `PATH` instead would be a different list under the same heading — the app is a GUI process, the
   router is a launchd agent, and R6 exists because those differ. So the sheet is built, attached
   to the Settings window, and says what it will show and why it cannot yet. The first draft of the
   plan parked it outright; the out-of-family review called that an excuse against this repo's own
   two precedents (`SURF-010`'s pair sheet, `HeldVersionSheet`'s dimmed offers) and was right.
2. **The 30-day undo is not a thing this router does.** `ConfigWriter.backUp` keeps
   `backupsKept = 5` — five writes, not thirty days — and no control-API method reports a backup
   count, an age or a policy, so even "the last five are kept" would be quoting a constant the app
   cannot read. **Nothing was added**: the build never carried the claim, and this item did not
   introduce it. The gate table's "30-day undo stated on the surface" is therefore unmet by
   decision rather than by omission.
3. **`official` is drawn without the publisher grid.** `RegistryEntry` has no publisher field;
   `source` is which index supplied the row, not who published it. The fixture's names are
   `github`, `deepwiki` and `ai.smithery/Hint-Services-obsidian-github-mcp`, so a namespace parse
   would invent the ownership claim this sheet exists to disclaim. Grouping by `source` instead was
   rejected on this module's own note: a figure must come "never off `sources.official`, which is a
   pre-merge, pre-slice count of a different set." The omission is stated **on the surface**
   (`OfficialMarkCopy.publishersUnavailable`), not hidden.

### The defect the first session shipped without seeing

`4c320a8` put `labelColour(for:)` into **both** button styles — a plain string replace matched the
`makeBody` anchor twice — and only `StandardButtonStyle` declares `@Environment(\.isEnabled)`. The
copy in `ProminentButtonStyle` had no caller and no symbol in scope, so the package did not build.
That is why the first session's "committed and unbuilt" was true and its stated cause incomplete:
contention stopped the build from running, and a real error was waiting behind it.

Deleting the uncalled method compiles and keeps the gap. `ProminentButtonStyle` had **no disabled
treatment at all** — `--on-accent` on an unconditional `--accent` fill — so a disabled primary was
pixel-identical to a live one, against `DESIGN.md`:443 and :491.

**The design of record does not settle it by drawing one, and that is a finding rather than a
shrug.** None of the mock's 29 `btn primary` instances is disabled, *and its CSS would not dim one
either*: `.btn:disabled` (:679) and `.btn.primary` (:680) have equal specificity and `.primary` is
declared second, so a disabled primary would keep its accent fill, its accent border and its
`--on-accent` label, differing from a live one only by losing its shadow. Reported as a fault in
the mock rather than copied. What ships is what the mock's own `:disabled` rule *says*, applied
without the cascade accident: `--f3` behind `--t4` with a `--line` bezel, same height, same
position. `--t4` is under the floor in both appearances and claims the `disabled` exemption by
name; `ButtonPaletteTests` asserts the token that carries it.

Both styles now read `isEnabled` from a nested `View` rather than from the `ButtonStyle`. A style
is not a `View`, whether SwiftUI installs a style's dynamic properties has moved between releases,
and a disabled button rendering at full strength is a defect no compile catches. The question is
removed by construction rather than measured around.

## Deviations from the plan, each with its reason

- **Phase E — the fidelity surfaces — was not started.** The plan scoped six
  (`quarantine`, `confirm-remove` on both hosts, `queued-detail`, `official`, `path`). None was
  written. A `<surface>.layers.json` is only worth committing once its gate has been run against it,
  and `mock-fidelity-gate.sh` needs the `MEASURE` build — a *second* compilation of the UI target,
  when the first never completed. A manifest committed without a run is the stale-ledger failure
  that script opens by warning about. Owed.
- **`SheetFrame` was not unified**, as planned (§6 of the plan). Six sheet frames remain.
- **Multi-select removal on Cleanup was not built**, as planned (§4.2). It is a Cleanup write-path
  feature rather than a sheet.
- **Error text still reads `ColorToken.fail`.** Four *buttons* were moved to the role; the error
  strings on five surfaces were left. That is `DESIGN.md` §10's open per-surface item, not this
  brief's clause about button roles, and moving them would widen the diff past what the item asks.
- **`SheetGate` lives in its own file** rather than inside `RouterSheet.swift` as the plan says.
  One 450-line file for three types read worse than two.

## Implementation assumptions

- **Host ownership is a test-time fact, not a compile-time one** — assuming the nested-group shape
  (rather than one exhaustive host over a flat enum, which would need `ShellModel` threaded into
  the four boards deliberately built without it, or a `default:` arm in each of six hosts, which
  the review objected to correctly).
- **`Kind` marks the three build-only sheets with a leading `-`** so the mock comparison can
  exclude them by prefix — assuming that over a second enum, which would be two inventories.
- **The `official` sheet's entry point is the mock's quiet `What is official?` control alone**
  (`design/mcp-router-console.html:2851`) — assuming that rather than also building the Publisher
  segmented filter beside it, which the build does not have and which is Discover's scope.
- **`request(_:)` returns the sheet it opened and leaves `sheet` untouched for a non-sheet gate** —
  assuming an ungated action should not shut a sheet the user opened (asserted by
  `ungatedRequestDoesNotCloseAnOpenSheet`).
