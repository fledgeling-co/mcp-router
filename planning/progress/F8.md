# F8 — cross-harness skill profiles

**Branch:** `ai/n4` · **Spec:** `planning/specs/spec-F8.md` · **Plan:** `planning/plans/plan-F8.md`
**Base:** `08a24ed` · **Status:** ready to verify. Not merged, not pushed.

## What the item turned out to be

The brief proposed a pusher: define a bundle centrally, propagate it to every harness, one click
aligns them. Reading the machine first turned that around. **The propagation already existed, done
by hand with symlinks, and a third of it had rotted with nobody told.** So what ships is the
reading and the projection, and the push is refused with its two reasons written down.

Measured 2026-08-29, read-only: `~/.cursor/skills` holds 87 entries, all symlinks, **27 dangling**,
86 of them into `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/` — a path an upgrade
replaces, so the links break as a consequence of keeping Claude current and the harness that loses
the skill is not the one the upgrade happened in. `~/.claude/skills` and `~/.cursor/skills` share
**one** name; the union across every root is 130. Claude Desktop and grok have no skills directory
at all; Codex and ChatGPT share one.

## Which half of R29's split each piece is on

Stated because the brief asked for it, and the honest answer for everything touching another
harness is *neither of R29's two*:

| piece | half |
|---|---|
| the profile record at `<router home>/profiles` | the router's own disk |
| reading a harness skills root | read-only, and it is the deliverable |
| a step that would add or repair a skill link | **durable** — the bytes would stay, and no protocol makes a live session re-read a skill |
| a step that changes the served server set | **tell, in the other binary** — `list_changed` is `src/livereload.ts`, TypeScript; `git grep list_changed app/Sources` is empty |
| a step needing a harness MCP config write | **refused** — spec-R7 §7 |
| telling a live session | ask only, and R29 §2.2 already ships it default-off |

All three `ProfileReach` cases occur on the real machine, so none is a branch nothing takes.

## The defect the suite found rather than reasoned about

`ControlAPIRequest.isMutating` is `POST || DELETE || PATCH`, ported from `src/control.ts`.
**PUT is not in it.** The profile write was written as a `PUT`, and C5 recorded
`(untokened.status → 200) == 401` — an unauthenticated write, in a green tree. No route served PUT
before this family, so nothing was ever exposed; this would have been the first.

Taken as **POST**, not by widening `isMutating`: that property is derived from the reference in
both directions by `parity-manifest-check.sh`, and widening a ported gate to buy a verb is the
wrong trade. `C6` holds the invariant for the next route here, parameterised over PUT, HEAD,
OPTIONS and TRACE, and the acceptance lane asserts the 405 on the wire.

## Instruments, and each one watched failing

1. **The acceptance lane** — `skillRoots` dropped from `RouterServiceDispatch.controlDeps()`: the
   daemon answers 503, six assertions redden, the unit suite stays green. That is the
   missing-wiring class (`D-p1-a`, `control-registry-search`) and it is the reason the lane exists.
2. **C6** — `case "POST", "PUT"` restored: the issue is recorded on the `PUT` argument alone and
   the other three pass, so the assertion is about the gate's set rather than a handler that
   refuses everything.
3. **S1** — the dangling classification, watched in both directions inside one test: the target is
   deleted mid-way, so `linked` and `dangling` are two answers from one reader.
4. **`no-harness-skill-writes.sh`** — its selftest plants eleven appliers with their expected exits,
   two instrument failures, and a mechanical check that every alternative in the mutating
   vocabulary fires on a probe. **That check was itself watched failing**: eleven alternatives
   matched no probe because an unquoted `[^A-Za-z]` in the harness was read as a glob class and
   emptied them — a selftest reporting a pass for a set it had not exercised. Quoted, and all
   eighteen fire.
5. **P7 is a declared miss** — an applier split across two neutrally named files outside the seam
   walks through, planted and expected, so the limit shows up in a run rather than in prose.

## What is not here, and why

`F8-C2` the Mac profile board (a board is converted under M23 against the console reference, not

R7-C4 records). The TypeScript router gains nothing: R28's store is Swift-only, so a `/profiles`
family there would select over a store that binary does not have.
