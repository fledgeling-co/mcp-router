# M12 — staleness and an as-of time inside a destructive dialog

**Branch** `ai/m12` · **Base** `main` at `87e16dc`, merged forward to `9d4da76` · **Status** ready
to verify again after gap-fix 1 — not verified here. Verified `Needs More Work` at `3367f72` on
2026-08-23; the five findings and what closed them are the last section of this note.

M12 arrived with no brief and no spec: its rows in `ORCHESTRATOR.md` and
`planning/features-to-triage/LEDGER.md` were its whole record — cited by row rather than by line,
because every runner in the fleet appends to both every hour, and the two numbers this note used to
carry had drifted onto unrelated rows within a day. Both rows were written from M7's Phase D critic,
findings 4 and 8 — graded VALID, deferred rather than fixed, with the reason that
*"marking staleness inside a modal is a design decision, not a defect this item may settle alone"*.
So this item wrote its own brief, spec and plan, and the design decision is the deliverable as much
as the code is.

## What was wrong

Two dialogs in `CleanupSheets.swift` stated consequence figures taken from the last successful poll,
in the present tense, with no marker when that reading was stale and no as-of time.

`CleanupBoardModel.LoadState.stale` keeps the previous reading when a poll throws, and
`LoadState.reading` returns it. The board draws `StaleReadingBanner` above the table in that state —
and a modal covers the banner it would otherwise sit under. That is how a board which already
discloses staleness came to have two destructive dialogs that do not.

`Reading` carried no timestamp at all, so the as-of time finding 8 asked for could not be stated:
nothing stamped the reading.

## What landed

**One new field.** `Reading.observedAt`, stamped from an injected clock at the instant `servers()`
returns — before `skills()` and `usageSummary()` are attempted, so the age it implies is never
*younger* than the truth. A staleness disclosure that errs has to err old.

**The stamp is a clock time, not an elapsed age, and that is the decision worth reading.** The plan
said "taken 3m ago" and the plan review killed it: a relative phrase is computed when the view body
runs, and a modal's body does not re-run while it sits open — this board has no timer and nothing
the sheet reads changes with the clock. A dialog left open for a quarter of an hour would have gone
on saying "3m ago": a figure reading as fresher than it is, which is the defect M12 exists to
remove, rebuilt one line below the fix. An absolute stamp is equally true at every instant the
dialog is on screen, and an "as of" *time* is what finding 8 asked for. The date is added when the
reading is not from today.

**The treatment is a value, not a branch in a view.** `CleanupPresentation.Provenance` — `.none`,
`.quiet`, `.marked` — decided on the model and rendered by `ProvenanceNote`. Stale draws the
`Banner(.warn, .attention)` that `StaleReadingBanner` and `PartialIndexNote` already use, so §6's
one-wording-per-state holds between the board and the dialog covering it, `--attn` stays on the
glyph in its `pairedWithAWord` role, and the two treatments differ structurally rather than only in
hue. Fresh draws a `--t3` caption. Because the decision is a value, "a stale reading is marked and a
current one is quiet" is a claim a test makes rather than one a reader takes on trust.

**Staleness discloses; it does not dim.** `.stale` means the last *read* threw, not that the write
will, and dimming would refuse the act hardest in the case a reader most wants it — a wedged router
whose history someone is trying to reset. The pre-existing refusal (the candidate has left the list,
so there is no consequence to disclose at all) is untouched and is now exercised rather than
grepped: `removalRefusalReason(for:)` moved onto the model, which is what `.disabled` and `.help`
both read.

**The shared consequence sentence is byte-identical.** Two boards call `resetConsequence` so they
cannot tell the user different things about the same irreversible act, and it carries five red-green
assertions from M7's finding 1. Provenance sits beside it, never inside it, and a test fails if a
provenance phrase migrates into it.

## The thing that went wrong, recorded rather than tidied

**A commit swept up a live mutation.** `git add -A` was issued between one mutation's apply and its
revert, so `eaf4352` committed the M3 mutation — the one that makes a stale reading render as a
quiet caption — and the script's own `git checkout --` then restored the file to the state it had
just been told was HEAD. The pass caught it: the baseline that follows the mutation table came back
**red with exactly M3's two issues**, on a tree `git status` called clean. Reverted in `3ab6fa7`,
green there. Left in the history rather than rebased away, because a mutation pass whose log reads
red-then-green either way is exactly the failure this discipline exists to catch, and the next
runner should know the hazard is real on a shared machine.

## What I could not settle

**0 · One acceptance run failed the invisibility invariant, did not reproduce, and cannot be
attributed.** The first run of A15c passed all eight assertions and then failed its last step —
`the removal dialog brought MCP Router to the front`. Two runs since are exit 0 with the frontmost
app never becoming MCP Router. It could not have been attributed even had it reproduced: `axkit
front` compares an app **name**, so any MCP Router build on a machine running several worktrees
fails this gate identically to this one doing it, and the first run coincided with a load average
above 130 and other Mac worktrees building. `open_sheet` now runs the check itself so a future
failure names its step; making the check pid-aware is `axkit`'s verb and every caller of
`check_invisible`, which is a shared harness surface and not a copy item's to change.

**1 · The stale marker has no rendered proof.** `LoadState.stale` is reached only when a poll fails
*after* one has succeeded, so producing it in a running build needs a fixture that answers and then
refuses. `FixtureControlAPIClient` is a stateless `struct` with one response per scenario, and
giving it a call counter is a change to the fixture layer every board's acceptance script runs
against, with a parity row of its own. The marked treatment is proved at the model and value layers;
that it *renders* as a banner rather than a caption is not proved by a rendered pass. The
`cleanupSkills` scenario is the precedent for adding one — its own doc comment says it exists so a
state unit tests could only reach by building a reading directly could be photographed. Follow-on,
named, not claimed.

**2 · Activity's reset dialog is not fixed, and the reason is a bigger defect than M12's.** It
offers the same act through the same shared sentence, and the out-of-family lane recommended
extending scope to it. Measuring the figure each dialog passes refuses that: Cleanup passes the
unbounded per-server tally from `usage.summary()`, Activity passes `records.count` — the size of a
**500-capped** ring window (`ActivityRecords.capacity` = 500 at `ActivityRecords.swift:18`, matched
to `RING_SIZE` at `src/usage.ts:52`; the *route* defaults to 200 at `src/control.ts:496`, and the
500 is what `ActivityModel.swift:162` asks for) — and `usage.reset()` discards the ring, the
unbounded tallies **and** two on-disk log files (`src/usage.ts:281–293`). On a router with 812
recorded calls the two dialogs say **812** and **500** for the same button. Dating Activity's number
would have made that dialog read as better disclosed than it is while the larger understatement
stayed unsaid. It needs a different fix — state what the figure actually is, or fetch the summary
tally, which means a new request on a board whose design deliberately makes exactly two. Its own
item.

**3 · A poll where `servers()` succeeds and `usageSummary()` throws silently drops the call count.**
`load()` writes `.loaded` with `recordedCalls = nil` and no partial marker. It is not dishonest —
the consequence then says the router has not stated how many, which is true of that reading, and
keeping the old count would be exactly the defect M12 fixes — but §5's Partial asks for the loss to
be said, and the board says nothing. On `main` as well as here. Found by the plan review; a board
change rather than a dialog one.

**4 · `SkillProvenanceSheet` draws `CheckCopy.ownerChanged` as body text in `ColorToken.attention`.**
`--attn` is declared `pairedWithAWord`, whose recorded ratio on the light ground is **2.31:1** — a
fine dot and an unreadable label — and `--attn-ink` is the `text`-role twin that exists for this.
Found while choosing the tint for the marked treatment. M7's line, not a destructive dialog, and it
belongs to the per-surface contrast sweep `DESIGN.md` §10 asks for.

## A dependency bump this item refused to carry

The first `make build-mac` came back `BUILD SUCCEEDED` and then **failed its own freshness gate** —
*"the Debug sources changed while the build was running"*. What moved was `app/Package.resolved`:
SwiftPM had floated `eventsource` from **1.4.2 to 1.5.1** during resolution. It is a transitive
dependency of `modelcontextprotocol/swift-sdk`, which `Package.swift` pins `exact: "0.12.1"` — the
SDK's own range is what floated, and `SWIFT_PRACTICES.md` §8 asks for exact pins precisely because
that SDK is pre-1.0 and warns a minor bump may break its API.

Reverted rather than committed: an unrelated dependency bump riding on a copy item is exactly the
diff-scope rule this repo states. The rebuild ran with `-onlyUsePackageVersionsFromResolvedFile` and
`Package.resolved` came back unchanged, so the product under test is the tree as committed.

Worth someone's attention as its own item: nothing in `make build-mac` passes that flag, so an
ordinary build on a fresh worktree floats a transitive pin and then trips the freshness gate with a
message that names the symptom rather than the cause.

### 1 · The A15c row that could not fail — the blocker

The row published *the as-of stamp is absolute* and greped `reading taken $shape` for six relative
shapes. The sentence hardcodes `at ` after `taken`, and `shortAgo` puts a digit where that pattern
wanted the unit, so `reading taken at 3m ago` — the regression the plan review killed, and the one
thing this item's central design decision exists to prevent — walked past the row claiming to prove
it absent.

It now reads the text after `reading taken at ` and requires a clock time, with a non-empty check
above it so an empty extraction cannot read as agreement. **Armed by planting rather than by reading
the new regex**: with `asOfLabel` returning `shortAgo(date, from: now) + " ago"`, rebuilt, the app
speaks `'now ago'` and the gate exits 1 at that row; reverted to a byte-identical file, it is
`25 passed, 0 failed`, exit 0, twice. Both forms were then run against the same planted sentence
offline, and the old one passes it while the new one fails it and still passes the correct sentence
— so this is not a blanket refusal.

**What it still does not cover.** The removal dialog's stamp keeps its presence assertion
(`was read at`) and gains no absoluteness assertion. `fail` exits, so one plant arms one row, and
adding a second assertion here would ship an instrument nobody had seen fail — which is the defect
being fixed. `asOfLabel` is the single source of both stamps and mutation M6 arms it at the unit
layer. Recorded as a declared gap rather than closed.

### 2 · A green unit run stamped to a tree where it is red
