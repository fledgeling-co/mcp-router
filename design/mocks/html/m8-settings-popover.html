M8 — Settings, the menu-bar popover, and the quarantine route

Three surfaces that finish the Mac app: the pane that says what the router is, the glanceable instrument that lives in the menu bar, and the one press that gets a held tool description in front of a human. Every value drawn below is one the router actually serves — the four groups this pane ships are what survived that test, and §10 records what did not, with the measurement that ruled it out.

§1Settings — the populated pane

Grouped inset cards; label-left, control-right, on one shared axis across the whole pane rather than per card — the label column is a fixed 150pt so the Router card's values and the Menu bar group's checkbox line up with each other. Section headers are sentence case in --t3 (§3.2). Instrument values are SF Mono; prose is not (§2).

§2Settings — the nine states

DESIGN.md §5. The interesting one is partial, and it is peculiar to this pane: Settings is the only surface in the app that still has something true to say when the router is unreachable, because the token and the home path are on this Mac's disk. So the router card degrades and the rest of the pane keeps working, rather than the whole pane becoming an error.

Success is in place, and there is no toast

§5: macOS does not toast a click. Ticking Show MCP Router in the menu bar makes the item appear or disappear immediately — the change is the feedback. Pressing Forget the stored token flips the Token row to "Not stored yet" and dims the button in the same frame. Nothing confirms, nothing announces, and nothing needs dismissing.

§3The status item, and the one rule it obeys

A template symbol, so macOS tints it for the menu bar's appearance and it inverts correctly when the bar is light. It carries a dot only while at least one server wants a decision — MCPServer.needsAttention, which is already the Servers badge's source, so the bar and the sidebar can never disagree about whether something is wrong.

The dot is never --fail, even for a tripped server. Both conditions end in the same place — a human deciding something — and two dot colours in a 16pt glyph are two things to learn for no gain. The distinction is drawn in the popover, where there is room for a sentence. --live never appears in the bar at all: a running child process is the normal state, and marking it would make the icon change constantly, which is the exact failure the brief names.

Liquid Glass (§3.3 — floating chrome only), radius 20 with concentric children at 14. Three zones and one action. It answers one question and vanishes; there is no navigation in it and no setting.

§6The quarantine route — M3 owns the sheet

The brief asks for a surface that shows the before/after diff of a changed tool description and requires an explicit accept. That surface exists and is good. HeldChangeSheet renders one ToolChangeCard per ToolChange with was and now fields, names any invisible codepoints the description carries, and offers Remove server / Keep serving the old text / Accept the new text with the accept button disabled-with-a-reason while the diff is loading, failed, or empty.

What M8 adds is the shortest path to it. Today the only way in is: open the app → land on whichever pane was restored → go to Servers → notice an amber row → select it → find the banner in the inspector → press Review. A held tool description is a server trying to redirect an agent, and six steps behind a window that may not be open is not where that belongs.

Status itemTakes its dot the moment needsAttention becomes true.

One pressActivates the app, selects Servers, selects that server, opens its held-change sheet.
→
M3's HeldChangeSheet Unchanged. M8 writes none of it.

The routes for the other two causes differ, and that is deliberate. A server that needs authorising and one that failed to index both land on Servers with that row selected and no sheet — their next action is in the inspector, and opening a sheet the user did not ask for would put a modal in front of a decision they may not want to make yet. Only the held change opens a sheet, because only the held change is a security decision the product is actively holding bytes back for.

This is the one press in the app that legitimately activates it. Everywhere else the popover is the surface; here the destination is a window. Pressing the row calls NSApp.activate and closes the popover — a sheet behind a menu-bar popover on an unactivated app is a sheet nobody can reach.

§10What the brief named and this pane does not draw

Each of these was measured against the merged tree rather than assumed absent. A control for a mechanism that does not exist is worse than no control: a dimmed "RAM budget" slider tells the user the budget exists and is merely off, and the next person to read the code believes it too.

Named in the briefWhat is actually thereDisposition
Router port and lifecycle port and idleMs are served on GET /servers. Nothing writes them: isControlPath admits only /servers, /usage, /registry (src/control.ts:206), and ServerPatch is per-server. Shipped, read-only, with the reason on the pane. Writing servers.json from the app would be a second channel, which the product's standing constraint forbids.
Warm-set RAM budget residentMb() exists in src/pool.ts:319 and has zero callers. It never reaches describe() and never reaches the wire. There is no eviction-by-memory mechanism anywhere in the router. Deferred child. Needs the router to serve the measurement and to implement a budget; both are R-lane. The warm set ships, counted from MCPServer.warm, with no megabyte figure.
Auto-update policy No updater exists in the app — no Sparkle, no update check, nothing that could obey a policy. Deferred child. The policy is the second half of a feature whose first half is not built.
Per-client install targets ClientConfigs.discover knows all six clients and their paths — and it lives in RouterCore, which app/Package.swift links from neither app, deliberately, so that reading a config file directly has to be added on purpose. Its own doc comment says writing back "belongs to a later item". Deferred child. Needs either a control-API endpoint or an explicit decision to give the app a second channel. That is a product decision, not a UI one.
The control token ControlTokenStore (keychain) and RouterTokenFile both exist and the live client already reads, caches and re-reads on rotation. Shipped. Presence, source path, and forget. The value is never rendered.
(prototype) Update promotion toggles Three toggles about promoting capability updates. There is no skills or marketplace model in the merged tree and no endpoint behind any of them. Deferred to whichever item owns capability updates (M4/M7).
(prototype) Paired devices Pairing, naming and revoking a phone. M6 owns it by its own brief. Not M8's, and building it here would give the product two pairing surfaces.
(prototype) Reset call history resetUsage() exists on the client and no built surface calls it. M2's child M2a, which also specifies a File-menu command. Left intact rather than half-built here; reported to the orchestrator.
