# J5 — put the router in a chosen state and read the boards

Evidence work, not feature work. `REQ-004`, `REQ-005` and `REQ-007` all carried evidence
`reported` — the project's own account of itself — and `reckon` classes that `unmeasured`. The
deliverable is the capability that makes them observable, plus the cases that then stand on it.

## What the boards actually said

One run, three arranged states, a reference router on `127.0.0.1:8955` under a scratch
`MCP_ROUTER_HOME` declaring three upstreams named `j5-{alpha,beta,gamma}-<nonce>`. The router's own
answer, read over HTTP by the harness at each shutter: **3 tools, 3 servers, 1 running, 1 at rest,
port 8955**.

| state | the board's header | running | sidebar `N of M` | `N at rest` | port | photograph |
|---|---|---|---|---|---|---|
| `cold` | nothing — `The router isn't running` | — | — | — | — | refused |
| `running` | `3 tools from 3 servers · 1 running` | 1 | `1 of 3` | `1 at rest` | `:8,955` | filed |
| `stale` | `3 tools from 3 servers · last reading, not current` | **absent** | **absent** | **absent** | `:8,955` | refused |

The stale row is the one worth reading twice. The totals stand — the servers really were read, and
a failed refresh is not evidence they went away — while every present-tense figure goes absent, in
three places drawn by three different pieces of code. The port stays, deliberately: `TrackerState`
documents it as not cleared by a failure, because a poll that did not complete is not evidence the
router changed its port.

`bin/forced-state-assert.py` ran **38 checks over the 3 states** and reported none.

## The defect, and why it was structural rather than an oversight

Every board this campaign has ever photographed was drawn by `FixtureControlAPIClient`.

`ShellClientFactory.choice(isDebugBuild:environment:)` had two branches: a Release build was always
`.live`, and a **Debug build was always a fixture**. There was no third answer. So a glass capture
proved the board renders a JSON file in this repository, and CASE-0166 says so in its own note —
*"ShellClientFactory makes a Debug build ALWAYS take a fixture, so no macos-glass capture is
evidence about a real reading"*. Two of the three requirements are about a board's relationship to a
**router**, and the third is about what a board draws when the router **stops**; neither question
had a lane on glass at all.

The trap inside the trap: `MCPROUTER_SCENARIO=live` was not a `Scenario` raw value, so it fell
through `Scenario(rawValue:)` to `.fixture(.populated)` **and said nothing**. A run that believed it
had asked for a live router got the populated fixture and a green.

## What was built

### 1. The hook — `ShellClientFactory` can choose the real router, at a router of the caller's choosing

`app/Sources/MCPRouterUI/Shell/ShellClientFactory.swift`

- `Choice.live` carries a `URL` instead of being a bare case, and a Release build returns
  `.live(shippingEndpoint)` **before any environment variable is read** — so a shipped build can be
  talked into neither a fixture nor a foreign endpoint. That second half did not exist before: the
  old suite proved a Release build could not be given a fixture and said nothing about where it
  points.
- `MCPROUTER_SCENARIO=live` selects `LiveControlAPIClient`; `MCP_ROUTER_URL` names which router.
  The name is reserved and a test holds it reserved — if a `Scenario` case with the raw value `live`
  were ever added, the branch would stop being reachable and the silent fallback would return with
  no line of the factory changing.
- **Loopback only.** `http` over `127.0.0.1`, `localhost` or `::1`, and nothing else. Anything else
  falls back to the shipping endpoint. A Debug affordance may not become an exfiltration route.
- **A chosen endpoint never touches the user's Keychain.** It reads that router's own token file
  under `MCP_ROUTER_HOME` through an in-memory store — the route `ControlProbe` already travels — so
  the user's real credential is never sent to a router this repository started.
- The event stream is pointed at the same router by the same rule. Splitting them would let a Debug
  build read one router's servers while streaming another's calls, which is the one input shape
  `ServerStateTracker`'s precedence rules cannot make honest.

### 2. The instrument — `bin/forced-state.sh`

Arranges three conditions against a real reference router and photographs the Servers board in each,
from outside, without ever activating the app.

| state | how it is arranged | tracker |
|---|---|---|
| `cold` | the router is **never started**, over a port proved free first | `.failed` |
| `running` | the router is up, declaring three fixture MCP upstreams this run named | `.loaded` |
| `stale` | the router is killed **underneath the same live app instance** | `.stale` |

`stale` must follow `running` on one app instance. A relaunch reaches `.failed`, which is the cold
state again and renders differently.

The router declares three copies of `bin/witness-fixture/fixture-server.py` — a real stdio MCP peer
— and `mcp-router index` is run against them, with one declared `warm`. That produces
`3 tools from 3 servers · 1 running` and `1 at rest`: four figures that are 3, 3, 1 and 1 rather
than 0, N, 0 and 0. An earlier draft declared `/bin/echo` three times and produced
`0 tools … · 0 running`, where two of the four checks compared 0 against 0 and could not have
failed.

### 3. The oracle — a second reader, not the app

At every state the harness reads `GET /servers` itself, over the same loopback endpoint, in a
different process from the one that drew the board, and writes what it got beside what the board
drew. Every asserted figure is compared against that reading.

The declared server names carry a per-run nonce, and the board's own port is checked. Those two
close the direction a matching figure cannot: a shell that fell back to the shipping endpoint would
draw `:8,879` and somebody else's server names, and fails rather than passing against the wrong
world.

### 4. The assertions — `bin/forced-state-assert.py`

38 checks over the three states. The ones that carry the weight are absences, and they are asserted
as absences — no digit in that position, never a dash or a placeholder, because a placeholder is a
figure of its own:

- **stale**: the header withholds `· N running`, the sidebar readout withholds
  `N of M declared servers running`, and the Signal Path withholds `N at rest`. Three independent
  absences over one promise, in code that shares no line — a guardrail that held in one place and
  not the others would pass a single-predicate check.
- **stale**, the direction people forget: the servers that **were** read are still shown, the same
  number as while the router answered. A board that cleared itself would satisfy every absence check
  above while destroying data no source said was gone.
- **cold**: no totals, no running count, no readout, no at-rest count, no port, and no server row —
  and `The router isn't running` in `ControlAPIError`'s own wording.
- **every state**: no memory figure and no saving claim. `DESIGN.md` §6 names the fabricated memory
  saving by hand, and the check is run per state so a guardrail that held on one board and not
  another cannot pass on a single instance.

### 5. The shutter is not trusted either — `bin/paint-check.py`

The first two runs of this lane filed photographs of a window that had never drawn.

`screencapture -x -l<CGWindowID>` returns whatever surface the window server last composited, and
against a **live** launch that is behind everything, that is nothing: window chrome, a title, and
not even the sidebar. It exits 0 while doing it. The cold and stale frames came back byte-identical
to each other — sha `84a469099e7c`, 267622 bytes both — while their accessibility trees differed by
26 rows. The pictures agreed about a state the app was not in, and nothing in the capture channel
said so.

**Why no lane had met this before is the interesting half.** A fixture launch photographs correctly,
because `FixtureControlAPIClient` has its data at the first render and the first paint therefore
carries the board. A live launch does not: the window exists before the first poll answers, and by
the time the board has something to draw the window server has stopped compositing it. The window
never recovers — watched for 16 seconds at 2-second intervals, the same dump that reports a 980x620
window reports its sidebar at y=-537 with a height of 1964 on every sample. Hide-then-unhide, a
navigate-away-and-back reselect and a resize were each tried and each left the surface
byte-identical.

So every frame is checked before it is filed, and the check has **no threshold**: the sidebar's
rectangle must lie inside the window's, which is an exact invariant of a laid-out window and exactly
what an unpainted one violates. A colour count over the sidebar column was tried first and rejected
— the unpainted frame is not blank (traffic lights, toggle glyph, rounded corners, shadow: 146
distinct colours against 715 painted), so it separates only with a floor chosen after seeing both
numbers, which is fitting a threshold to two samples. The count is still printed, because it is what
a reader wants next; it decides nothing.

A refused frame is deleted and the state records why. `CASE-0198` is filed `n/a` with that reason
rather than carrying a picture of a window that never drew.

### 6. The arm — `--control`, in `make lint`

Almost everything above is an assertion that a string is **not** in a file, which is the exact shape
`sweep-control-gate.py` exists to distrust. `--control` builds a scratch observation set in a temp
directory that is never this campaign, proves the clean set passes, then plants one defect per check
— 38 of them — and requires each to be seen. **A check with no mutation behind it fails the control
rather than being counted**, so the arm cannot fall behind the assertions it arms.

It is hermetic: no router, no build, no display server, no Accessibility grant. That is why it can
live in `make lint` while the lane it arms cannot.

## What this does not reach

- **The cold and stale states have no photograph.** They are held in the AX plane by CASE-0197 and
  CASE-0199 over the same run; what is missing is evidence that those states reached the screen, and
  §5 above is why. Closing it needs a capture channel that does not depend on the window server
  having composited an occluded window — `MeasureDump`'s `NSHostingView.cacheDisplay(in:to:)`, which
  reads the view's own backing store, is the one this repository already has.
- **SURF-009 is not bought by this hook.** The menu-bar popover is unmeasured because
  `NSStatusItem` is not an `AXPress` target while MCPRouter is backgrounded and this campaign never
  activates — an activation constraint, not a state-forcing one. Choosing a live client changes
  nothing about it. The route that would buy it is the same `MeasureDump`, which already renders
  `.popover` offscreen under `.prohibited` and takes a `FixtureControlAPIClient`; giving it a
  `--live-from` argument, as `--document-from` already is, would put the popover on this lane's
  oracle and close the raster gap above in the same change. That is a second heavy build
  (`MCP_ROUTER_MEASURE=1`) and a second lane, and it is left undone rather than claimed.
- **One board, three states.** The sweep is over the accessibility tree of the Servers board. A
  figure drawn on a board this run did not visit, or painted without reaching the AX plane, is
  outside it. Three boards are not nine.
- **The evidence words were not edited.** `REQ-004`, `REQ-005` and `REQ-007` still read `reported`
  in `inventory.json`. What changed is that passing cases now cite them from a lane with an external
  oracle, which is what `reckon`'s `backed_by` was added to require. Moving the word is a
  judgement for whoever adjudicates the campaign, and moving it here — in the same change as the
  cases that earn it — would be indistinguishable from the re-label the field exists to catch.

`make lint` and `make test` each went red first, and both reds were this feature's own.
`no-raw-design-values.sh` and `ShellIntegrationTests.theClientIsTheOnlyChannel` — two independent
gates on the same A36 rule — caught the first draft assembling a `URLSession` inside
`ShellClientFactory`; the wiring moved to `LiveControlAPIClient.init(scratchAt:)`, where the type
that owns the channel lives, and both went green. `reader-accounting.py` then caught
`paint-check.py` discarding blank dump lines silently; the drop is declared and the pinned count
moved from 39 to 40 in the same change.

One further failure was measured and is not this branch's:
`OAuthWireTests.cancellationResumesTheWaiter` failed once during a full run at load ~400 across 16
cores, and passes in isolation in 3.157s. It is a wall-clock test (a 50ms budget read after a
3-second sleep) in `RouterCore/Auth`, which this branch does not touch, and it passed on the final
full run.
