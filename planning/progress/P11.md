# P11 — nothing prevented a sixth vector that re-types its reference

Five parity vectors were found carrying a hand-copy of the reference expression they exist to pin.
Each was proved blind the same way: mutate the reference, and `make parity-regen` stays at exit 0.
All five are closed on `P9`'s branch, and P9 said the honest thing about the sweep that found them
— *"nothing prevents one. The sweep is a snapshot and will need repeating."* This is the standing
version of that sweep.

## What shipped

`planning/pin-class-gate.py`, in `make lint`. Every generator region that writes a committed vector
declares a pin class, and the class is enforced rather than recorded.

| | |
|---|---|
| Population | the 28 files in `app/Tests/RouterCoreTests/Vectors/`, reached through the 12 tracked `.mjs` under `scripts/` |
| Classes | 24 `src-export`, 4 `platform-builtin` |
| Carried | 5, by name, closing with `P9` |
| Arms | 5 on every invocation (`--control`), 7 in `null-run-gate.py` |
| Runtime | under a second, hermetic, no node and no `dist/` |

The four `platform-builtin` vectors are `json-roundtrip`, `iso8601`, `js-to-number` and `url-parse`
— each computing its expectation live from a builtin in a closed vocabulary of five names. The
vocabulary excludes `localeCompare` on purpose: the registry has its own comparator, so that is a
second copy and `locale-compare` is a `src-export` vector.

## Why an unannotated vector is the load-bearing rule

A gate that only re-runs the sweep is another snapshot with a cron attached. The property that
makes this a prevention is that a writer no annotation covers is a finding — so a sixth vector
added tomorrow fails until somebody says what it pins. Watched: planting one exits 1 and names it.

## The rules, and what each was measured against

R0 requires a `src-export` region to reach its declared exports through a binding resolved back to
`require(join(distDir, '<module>.js'))`. R1 refuses seven computation constructs inside such a
region. R2 holds `platform-builtin` to the closed vocabulary and to no reference binding at all.
R3 refuses a template literal of 40 characters or more that appears verbatim in `src/`.

Every threshold is measured rather than chosen. The seven R1 patterns fire on exactly the four
re-typed regions in `scripts/parity/` and on none of the nineteen compliant ones. `.toISOString(`
is deliberately not among them even though `iso8601` pins it: a seeded usage record stamps its own
timestamp, so the pattern fires on legitimate input data. `?? null` is likewise not among them,
because coalescing an absent member to `null` is JSON projection where `?? 200` is a default
re-typed. R3 is restricted to backtick literals because a 48-character plain string in this corpus
is a case input the reference also spells — `P9`'s corrected auth generator still carries one, and
reddening it would punish the fix.

**The rule set was checked against the tree that fixes the defect, not only the tree that has it.**
Run over `P9`'s generators with an empty carry set, it reports `28 compliant, 0 carried` at exit 0.
Run over this tree it reports `23 compliant, 5 carried`. The same rules distinguish the two, which
is the evidence that they are aimed at the defect rather than at the shape of the code.

## The carry, and the escape its own arm found

The five cannot be fixed here: their fix adds four production exports to `src/` and is `P9`'s
branch. So they are carried by name in the gate's `CARRY` constant, each with the item that closes
it, each region also carrying a `// pin-carry:` line, and the set printed at the top of every run
so a green never reads as clean. A carry cannot be declared into existence — a name absent from
`CARRY` is a blocking finding however the region annotates itself — and a carried region that
breaks no rule is itself a finding, so `P9` must delete its entries in the same change.

The first version carried the name alone. Re-declaring `locale-compare` as
`platform-builtin — String#localeCompare` then made its finding vanish and the run exit 0: the
vocabulary check fired and the carry absorbed it. Re-labelling was the cheapest way to silence the
gate, and it was found by running the gate's own arm against the real tree rather than by reading
it. A carry now names the class it excuses, and a re-label is a finding of its own.

## The two residuals, recorded as knowingly unguarded

Neither is closed here, and neither is in this item's scope; both are `P9`'s surface.

1. **The registry comparator's other two terms.** `locale-compare` shares only the ascending
   comparison with `searchRegistries`. The `?? ''` coalescing and the descending argument flip stay
   at the call site with no vector over them. Closing it needs a vector over the row comparator
   with a Swift consumer, which is new surface. `pin-class-gate.py` does not help: it asks whether
   an expectation was computed or copied, never whether the export it pins is the right one.
2. **`searchRegistries`' ordering as a whole** has no reference-driven vector at all, because no
   generator requires that module for it. On this tree nothing requires `registry.js`, which is why
   `locale-compare`'s R0 finding reads *nothing in this file requires `registry.js`*.

## What this gate does not measure, stated rather than implied

It does not prove a vector is aimed at the right export, and it does not prove the expectation is
the one the Swift consumer reads. A region can satisfy every rule and still pin a neighbouring
export; `scripts/parity/mutation-gate.sh` is the instrument for that. Helper following is one
binding deep and syntactic — a helper that calls a second helper is not followed, and the calls it
could not resolve to a definition are counted rather than dropped in silence.
