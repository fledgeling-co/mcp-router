# N8 — the inertness guard, made capable of failing

Brief: `planning/features-to-triage/a-security-guard-that-cannot-fail-now-guards-a-live-entry-point.md`
Branch: `ai/n8` · case allocated: **CASE-0262** · red-green arm: **A10**

## What was wrong

`MarkdownSecurityTests.htmlIsInert` was the only guard on the claim that embedded markup is never
obeyed, and it could not go red. Its four spellings named `javascript:`, no scheme, or nothing;
`MarkdownInline.sanitized` keeps only `inlinePresentationIntent` and an `https` link, so "no link"
was true of every one of them and "no `imageURL`" is true of every input the allowlist touches.

M30 wired `ControlAPICapabilityDocumentSource` into the shipped UI, so router-served third-party
document text now reaches this renderer in a Release build. The exposure is new; the guard on it
measured nothing either way.

## What holds, measured

The property is the platform's rather than this code's, so it was measured rather than asserted.
Under `MarkdownInline`'s own parsing options, `AttributedString(markdown:)` hands each HTML tag
back as characters and attaches `InlinePresentationIntent.inlineHTML` — an intent that names no
destination and carries nothing to fetch. Six spellings, no link and no `imageURL` on any of them,
characters identical to the source. It behaves the same under all four combinations of
`allowsExtendedAttributes` and `interpretedSyntax`, so no parsing-option choice of ours is what
makes it hold. Swift 6.2, macOS 26.6.2 (build 25G83), Debug, `swift test`.

So this was an evidence defect and not a live vulnerability, and the remedy is the assertion rather
than sanitisation the platform is already doing.

## A second, smaller finding, fixed in the same clause

The test's name — `inline HTML acquires no attribute of any kind` — was **false as written**, not
merely unfailable. The parser does attach one attribute to inline HTML, and `sanitized` carries it
through, because the intent branch of the allowlist keeps whatever bits the parser set rather than
an enumerated subset. `.inlineHTML` names no destination and `MarkdownInlineText` gives it no font,
fill or underline, so nothing is broken; but the guard was claiming something stronger than what
was true, and being unfailable is exactly why that survived review. The clause now pins the marker
by name, so an intent the parser has not attached before is a red rather than a shrug, and
`MarkdownInline`'s doc comment says the same thing where it previously said "no destination" and
stopped.

## What changed

- `app/Tests/MCPRouterKitTests/MarkdownSecurityTests.swift` — `htmlIsInert` rebuilt. Two `https`
  spellings added (`<a href="https://evil.example/x">press</a>`,
  `<img src="https://tracker.example/p.gif">`), because `https` is the one scheme the allowlist
  keeps and therefore the only one that can carry an interpreted `<a>` through to the assertion. A
  presence control runs the same reader over the markdown twin of the same destination first, so
  the oracle is known to be alive in the same run rather than in a different test. Three clauses
  where there were two: no link, handed back verbatim, and no attribute beyond the `.inlineHTML`
  marker. The `imageURL` clause is gone — it was true of every input by construction and is
  subsumed by the attribute clause, which can be false.
- `app/Sources/MCPRouterKit/Markdown/MarkdownInline.swift` — doc comment only. No behaviour change.
- `scripts/m19-red-green.py` — arm A10.

## The arm, and the measurement that makes it one

What keeps inline HTML inert is the platform, and a mutation pass cannot mutate the platform. A10
injects the toolchain change the guard exists to catch at the seam where this code hands the source
over: `MarkdownInline.init(markdown:)` rewrites `<a href="…">…</a>` into a markdown link before
parsing. The harness runs the named test alone, asserts `1 test in 1 suite`, requires a green
unmutated baseline, matches the recorded issue against the test's own display name, checks for a
trap, and restores the file.

- RED: `planning/test-campaign/evidence/runs/m19-red-green.a10.log` — all ten arms bit, exit 0.
- The counter-measurement, which is what makes this an arm rather than a decoration: the **same**
  mutation run against M19's four spellings **SURVIVED** —
  `planning/test-campaign/evidence/runs/m19-a10-unfailable-control.log`. The guard watched the
  parser start obeying HTML and stayed green. That is the defect, measured rather than argued.

## Re-witnessed, and the harness change that made it affordable

The arm and its counter-measurement were re-taken from scratch rather than read off the first
session's log — `planning/test-campaign/evidence/runs/m19-red-green.a10.rerun.log`. All ten arms
bit; A10 red against the shipped body (exit 0) and SURVIVED against M19's, reconstructed byte-for-
byte from `git show HEAD:` (exit 1). `MarkdownInline.swift` was hashed before and after every run
and came back identical each time.

`scripts/m19-red-green.py` gained `--only A10[,A3]`. A full pass is ~20 `swift test` invocations
and on this machine — load average 836-916 across 16 cores with eight runners live — it outlived
the window available to watch it, and three background attempts were killed mid-run. A filter
naming no arm exits 2 rather than reporting a clean sweep of nothing, and the summary line names
the subset so a chunk log cannot be filed as a full pass.

**One of those kills cost three wrong measurements, and that is filed rather than glossed.** A
killed run left arm A3's mutation inside `MarkdownInline.swift` — a file this branch already
modifies for a doc comment, so `git status` showed the same single `M` it had shown all along. The
counter-measurement inverted under it. Brief:
`planning/features-to-triage/a-killed-mutation-run-leaves-a-mutation-git-status-cannot-show.md`.
