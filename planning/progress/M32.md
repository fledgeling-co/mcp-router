## What changed

`planning/test-campaign/bin/vocab-differential.py`, rewritten. The burden of proof is inverted the
way `mock_fidelity.py` inverts it: **a control the build draws that the design does not specify is
a finding until a disposition says otherwise**, and the gate exits 1 on an extra with no row.

Four other things were wrong with it and are fixed in the same pass, each because the old shape
hid findings rather than because it was untidy:

- **The design half read the superseded prototype.** It rendered `design/mocks/prototype.html`
  through Obscura on every run, so the Harnesses, Insights and capability-document surfaces — the
  three newest Mac boards, and the ones most likely to carry build-side additions — were outside
  the comparison entirely. It now reads the committed `evidence/design-controls.json` census, which
  sources each surface from the design that actually draws it and records which in its own `source`
  field. **8 surfaces to 14**, and the browser leaves the loop.
- **The shell subtraction was the intersection of every board**, which is data-dependent. The
  sidebar's Cleanup row reads `Cleanup, 3 never used` in one dump and `Cleanup` in another, so the
  intersection dropped it and three boards reported `cleanup` as an addition of their own. It is
  now SURF-001's design set union its build set union its row-level controls; the last of those
  because `harnesses` and `insights` — the two destinations `M22` added after the prototype drew
  the shell — otherwise leak into every board as that board's own.
- **`NUMERICISH` was defined when the file was written and applied to nothing.** A dump label
  carrying a timestamp normalises to `j alpha t z` and read as a control. It now runs on the raw
  label and on **both** sides, so a control the design specifies with a version in its label leaves
  both sets together and cannot read as absent.
- **The tenant's own data is subtracted structurally rather than by name.** A control descending
  from an `AXOpaqueProviderGroup`, `AXOutline`, `AXTable`, `AXList` or `AXGrid` is one affordance
  repeated per fixture item — `design-controls.py`'s `ROW_CLASSES` rule read off the accessibility
  tree instead of the mock's markup. Deriving it keeps a capture fixture's server names out of a
  registry that would go stale whenever the fixture changed. **These are counted and named as
  their own class, never dropped**: a row-level addition is a real blind spot of this gate, and the
  header says so.

`planning/test-campaign/build-extras.json` is new: thirteen rows, one per extra, across three
dispositions. `defect` and `misattributed` each need a `ref` a reader can chase; `intended` needs
the reason and a framed citation.

## Arming

`--control` runs **14 arms** on dictionaries it builds, touching no file, and is enrolled in
`make lint` ahead of the gate itself. The four registry arms run through `findings_for` rather than
re-implementing it: an arm that re-implements the predicate proves the arm and not the gate, which
is this item's subject arriving inside its own fix. Both directions are armed — an extra that has a
disposition, and a well-formed registry row, must stay quiet.

Three further arms were run against the **real tree** rather than in memory, each restoring
afterwards:

| arm | exit |
|---|---|
| green, as committed | 0 |
| one disposition row removed (`best match`) | **1** |
| a disposition naming a control the build does not draw | **1** |
| the registry file absent altogether | **1** |

`build-extras.json` was restored byte-identical after each, verified by sha256 rather than asserted,
and the gate returns to 0.

**A negative result worth keeping.** The first cut of this rewrite scored zero controls on every
surface and reported it as a clean run. The cause was a mangled character class in a probe, not the
product — the all-zero shape is the signature this campaign already knows, and it was caught by
disbelieving a uniform result rather than by any check.

## The sweep gate reported the rewrite, and it was right to

After the rewrite the file carried one marker (`V3`) and fell below the discovery threshold of two,
so `sweep-control-gate.py` found it: *registered `grandfathered` and still in the tree, but
discovery no longer claims it*. It was not a narrowing — the file had renamed its denominator from
`rows` to `compared` while remaining the same absence sweep. Restoring the noun restored `V4`, and
it is recorded in the registry entry because it is a real property of lexical discovery: **a
rewrite that strengthens a sweep can hide it from the gate that checks sweeps.** The remedy was to
spell the predicate the way it reads, not to widen the reader — widening `V4` would change what 106
registered entries are held to, on this branch, for one file's benefit.

The entry moves `grandfathered` to `control`, so the grandfathered backlog falls 55 to 54 against a
count that is printed rather than blended, and declared controls run rise 31 to 32.

## What this does not reach, stated rather than implied

- **SURF-009 and SURF-028 are inconclusive**, not clean — no accessibility dump exists for the
  menu-bar popover or the capability-document panel, and the gate prints the design's control count
  beside the refusal. `examined=0` exits 2.
- **Row-level additions are counted and not judged.** Zero today on every board after the shell
  subtraction, but the class is real and the number is printed so it can be sized.
- **SURF-001's menu bar is outside the gate.** `SURF-001.menu.txt` holds 160 items and most are the
  host OS's — Finder, System Settings, Instruments — so a menu-level differential over it reports
  macOS as this product's additions.
- **Whether a control present in both sets does the right thing** is the effect ladder's question.
- The in-design-not-build direction is **reported and does not block**, because it already has an
  owner: `design-controls.py`'s census, `campaign.py check`'s denominator and `inventory.json`'s
  `controlsUnactuatable`, which is what produced DEF-062 through DEF-065.
