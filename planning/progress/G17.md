# G17 — the capability-document viewer has a case and a flow

**Branch** `ai/g17` · worktree `.worktrees/G17` · base `aab9190` · 2026-08-27

## What the gap was

M19 built the document viewer and M23 measured it against the mock. M30 built
`GET /servers/:name/document` and proved it with route tests, parity vectors and a two-router
differential. Both halves are sound. **The join was never a case:** no case covered a person opening
a capability, reading its read me and following it to the changelog.

M30's own runner made the point while building its look — every capture of that panel, M23's
included, was a picture of `CapabilityDocumentFixture`, a JSON file in this repository. It then
built `--document-from` and took two frames of a real one. That is one look, taken once, by the
person who wrote the code.

## The reach limit, stated

The route serves only servers declaring a package directory, and **0 of the 21 upstreams on this
machine declare one** — measured by M30 (`planning/evidence/M30-reach.txt`) and filed as its own
brief. So every case here is measured against a **constructed** server. That is labelled in four
places: this file, the harness header, the constructed package's own read me, and every row of
`captures.json`. What is not constructed is the router, the route, the HTTP transport, the Markdown
parser, the image resolver and the panel — those are the product, and the bytes cross a real
connection.

## What the run found that reading the code would not

- **`documentTooLarge`, not `tooLarge`.** Both routers spell the document-level refusal
  `documentTooLarge`; `tooLarge` is the *image* refusal one level in. A check written against the
  Swift enum's case name would have passed against a router that refused nothing. Caught on the
  first run.
- **A refusal frame's titlebar reads "Documentation".** The panel takes the capability's name from
  the document, so on any `unavailable` state it falls back to the generic word. Three of the
  refusals still identify themselves in their headline; `tooLarge` names the file and the cap and
  never the server. So a picture of that state is bound to its subject by its manifest row alone —
  the exact dependency the capture-lineage rule exists to remove. `DEF-060`, and check `G17-L2`
  fails if that set is ever anything other than exactly that one frame.
- **Rule 1 cannot be asserted by comparing endpoints.** The first armed pass failed with
  `ghostty -> EgressMac`: a third-party application took focus during the two minutes the run took,
  and a before/after comparison reported that as *this run* stealing the screen. The rule is a claim
  about the processes this harness starts, so a sampler now records the frontmost application once a
  second for the whole run and the assertion is that neither `MeasureDump` nor the router ever
  appears in it. 48 samples on the accepted run, none of them ours.

Four controls, three armed runs, twelve red-then-restored pairs, and every restore byte-identical to
the artifact taken before its fault.

**Reproducibility across runs is weaker than that, and the difference is measured rather than
assumed.** Two armed runs an hour apart produced byte-identical captures. A third, after the
`MeasureDump` binary was rebuilt, did not: `readme.served.png` differs from the earlier one in a
**157×4 pixel band at (942, 62) with a maximum channel delta of 1** — 628 pixels of 2,952,000, all
of them one least-significant bit apart, in a single strip of chrome. So the honest statement is
that this capture is byte-stable within a run and stable to ±1 LSB over 0.02% of the frame across a
rebuild, and a future gate comparing these PNGs by sha256 across machines would be pinning noise.
Every assertion here reads structure and colour out of the frame instead.

## Product changes

Three seams, all small, all disclosed:

- `CapabilityDocumentSheet.init(initialTab:)` — the tab is `@State` and switching it is a press,
  which a headless render cannot perform. Defaults to `.readMe`, so every existing caller and every
  existing dump is unchanged. Without it the panel's other two tabs had never been drawn carrying a
  document at all.
- `MeasureDump --document-tab` — passes that through.
- `MarkdownBlockView.figure` now measures the **refusal placeholder** as its own node
  (`figure-refusal`). Before this, a drawn figure and a placeholder saying it could not be drawn
  were the same `card` record, so no dump could say which refusal landed. The drawn `Image` is
  deliberately **not** measured: a node there would say two views differ and would not say that
  bytes arrived and were painted, which is the claim that had never been made — `CASE-0186` reads
  the pixels inside the card's own frame instead. `.measured` compiles only under `MEASURE`, so
  nothing reaches a shipping build.

An earlier revision of this branch measured the drawn image too. It cost one `extra` row on
`make mock-fidelity SURFACE=readme` (73 findings → 74) in exchange for a weaker oracle than the
raster already provided, so it was removed and the `readme.pairing.tsv` row adjudicating it was
reverted. The refusal node costs the census nothing, because it is drawn only when a reference is
refused and the M19 fixture's one image resolves. Confirmed by re-running the gate: **73 findings,
unchanged from `aab9190`.** The five capture sha256s are identical before and after that edit, which
is itself the evidence that the instrumentation does not alter what is drawn.

## One thing a later reader should not have to rediscover

Any plain `swift build` in this worktree — `make build`, `make test`, an editor building on save —
overwrites `app/.build/debug/MeasureDump` with a **non-MEASURE** binary that is executable, correct,
and unable to measure anything. It happened during this run: `make test` replaced the instrument
mid-item and the harness's next invocation exited 3. That is the harness working — it reports the
instrument as unable to measure rather than reporting the product broken — but the rebuild
(`cd app && MCP_ROUTER_MEASURE=1 swift build --product MeasureDump`) has to come after any test run
and before any capture.
