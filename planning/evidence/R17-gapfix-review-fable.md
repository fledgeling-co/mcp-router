🫥 Verdict first: the corrected claim structure holds together — "sufficient, not exclusive" for the one-shot observation and "exclusive for the standing partition" are claims about *different observables*, so there is no incoherence — but the folding left one pre-correction over-claim standing verbatim in both comment blocks, one internal contradiction between criterion 1 and R20, and the partition argument is now *under*-claimed in two places. Nine findings, ranked.

**1. The "including the row `index --force` had just written" clause survives the correction it contradicts.** (Q3 — the most important one.) Both the cause section ("every watch fire past the five-minute backoff re-indexed it and deleted the row again — including the row `index --force` had just written") and the `src/watch.ts` block (same clause) attribute the erasure of *that specific row* to the delete. Mechanically that attribution is exactly what was withdrawn: a row `index --force` writes *after* a fire's load at `:212` is never in `next` at all, so the delete never touches it — the stale save erases it. Only a row present at load takes the delete route. The owner ran `index --force` with the launchd agent live, so for the just-written row the eraser is genuinely either mechanism — which both files concede two paragraphs later ("consistent with either") while keeping the "deleted the row again — including…" clause verbatim above. Fix: "and the row `index --force` had just written was gone again — by the delete or by the stale save, whichever fire it fell into."

**2. Criterion 1's route bound contradicts R20 for the name-collision subclass.** (Q3.) "A server staged in `~/.claude.json` and never adopted into `servers.json` now gets a manifest row, and **no surface REPORTS it**" — false for R20's measured shape. The broken staged `db` was never adopted, and `/servers` *does* report its row, misattributed to the healthy configured upstream of the same name. The supporting sentence is correctly scoped ("a row keyed by a name that is not in `config.upstreams` is never joined…") but the paragraph's opening sentence is not, and "This is **strictly better than pre-fix**" fails for the same subclass: the R20 section itself says the misattribution *is* a regression — a wrong reason shown where pre-fix showed nothing. "Strictly" cannot survive a subclass the same document calls worse. Both sentences need the same-name carve-out and a cross-reference to R20.

Worse: criterion 1 says "Not held for four paths that never reach `buildManifest` at all — see *What the review lanes found* below, **F3**" — and the section it points at defines no F3. The four paths are never enumerated anywhere in the packet. A criterion's stated bound rests on a label with no referent.

**6. The coverage bound counts node sites and gestures at Swift.** (Q2.) "It does NOT cover the other four `saveManifest` call sites: `src/index.ts:146` and `:186` … `src/control.ts:262` and `:432`" — all four are node paths, yet the same sentence says the window exists "on both sides." The Swift twins (the index verb's and control API's `ManifestIO.save` sites) are asserted to exist and never enumerated, so "R19 owns the policy over all five sites" names a five that is really five-node-plus-an-uncounted-Swift-set. If that path is `control.ts`'s Swift twin, say so; if it is a sixth writer, the bound's exhaustiveness is false. Either way the bound is honest about node and silent where the header shows the universe is bigger.

**7. The isStale rebuttal is right about tool loss and wrong in its closing generalisation.** (Q4.) "There is no state the error row pins that the absent key left open" — R20 is exactly such a state: under name collision, the persistent error row pins a wrong, specific reason onto `/servers` that the absent key left blank, and the document *measures* it and calls it a regression. The rebuttal's actual argument is sound and sufficient against the lane's actual claim — `isStale` true for both shapes, `unionTools` skipping both, backoff keyed in `watch-state.json` either way, so *tool availability and retry behaviour* are equivalent. Scope the closing sentence to that and the bullet is clean. The second not-taken bullet (declaring the clobberer under its verb, naming the rest uncovered) is sound as written.

**8. The partition argument is UNDER-claimed — twice.** (Q1, and the explicit under-claim check.) "R19's window is **indifferent** to whether a server is staged" and "**Nothing** about R19 predicts which server loses its row" both give away strength the mechanics don't require. R19 is not indifferent — it is *anti-correlated* with the observed partition: a staged failing server is in every fire's hand, so the fire's own save re-writes its entry; the only rows a stale save can durably erase are those written by another writer for servers *not* in that fire's hand. An R19-only world therefore predicts `namecheap` — staged, indexed every cycle — *has* a row, and predicts the erasure victims are the unstaged ones like `lifeline`, whose row was observed intact. R19 doesn't merely fail to select the observed partition; it predicts its opposite. Said that way, the delete is not just "not merely sufficient" for the partition — it is the only candidate left standing, which is a stronger sentence than the correction currently dares. Relatedly, the bold heading ("sufficient … and not exclusive") is scoped to "the observable" without saying *which* observable; since exclusivity is retained for the standing partition three paragraphs later, the heading under-reports its own section.

**9. "Nothing reads it" survives in the node block after the same phrase was corrected elsewhere.** (Q3, minor.) `src/watch.ts`: "watch-state.json kept the reason the whole time, durably, and **nothing reads it**." The watcher reads `watch-state.json` every fire — the isStale rebuttal itself says "the backoff is keyed in watch-state.json either way." If "it" means the reason field, the sentence is defensible but the antecedent is ambiguous; the reads-versus-reports distinction was the lane's finding #3 and got applied to the manifest-row claim but not here. "Nothing reads the reason back to any surface" is the sentence that survives its own document.
