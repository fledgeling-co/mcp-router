## What was built

**The band.** `SignalPath.swift` draws a head — title, topology line, four-swatch legend — over a
rail of hub → arrow → jack field. `Jack.swift` draws one jack; `StatePlug.swift` draws the mark it
leads with, at the two sizes the legend, the jack, the table row and the inspector take it.

**The field packs rather than grows.** `LazyVGrid` with `GridItem(.adaptive(minimum: 132))`, the
direct translation of `repeat(auto-fill, minmax(132px, 1fr))`. Measured at 1280×820: four columns,
track pitch 140 = 132 + the grid unit, field width 1112 — which is exactly what
`SignalPathGeometry.jackFieldWidth(inBoardWidth:)` predicts.

**The geometry is a value type with invariants, not literals in a view.** `SignalPathGeometry`
replaces `BreakerGeometry` one for one — same `documentedValues` contract, same parity suite, same
argument for living in the headless target. Ten rows in a new `### Signal Path geometry` table.
`columns(inJackFieldWidth:)` is the CSS `auto-fill` arithmetic written out, which is what turns the
brief's *"two jacks fit beside an open inspector"* from prose into an assertion.

**The presentation layer is one chain.** `JackState` inherits `BreakerState`'s ordering unchanged —
running first, because the plug's meaning is the lever's — with `wantsYou` split into `held` and
`needsSignIn` because a jack carries a word as well as a colour.

**The retirement.** `Breaker.swift`, `BreakerGeometry.swift`, `BreakerState`, the nineteen-row
table, `BreakerGeometryTests`, `BreakerGeometryParityTests`, and the breaker's rows in `DESIGN.md`
§1, §7 and §8. Three consumers were re-homed rather than deleted, because each carried an argument
that outlived the element: the badge bump, the loading skeleton, and A7's cross product.

**The gate.** `VOUCHED_CONTROLS` gains `jack` and `signature`; `servers.pairing.tsv` gains the band
and four jacks.

## The plan's out-of-family review, and what it changed

`agy` / `gemini-3.7-flash-high` reviewed the plan adversarially over eight questions and returned
**AMEND** with four rejections. `codex` is down until 2026-08-27 and `grok`'s balance was
re-confirmed exhausted on 2026-08-22, so the Google lane is the gate rather than a downgrade.

Two rejections changed shipped behaviour and both were real:

1. **A warm running server would have drawn a countdown.** The first draft computed the jack's word
   from the same chain as its plug. `ServerSubtitle` has put `warm` above `running` since M3 because
   the reaper skips a warm server, so the band would have read `3:41 left` while the hub two inches
   above read `1 at rest` — two statements about one server on one board. The word is now computed
   from the state **plus** `warm`.
2. **`at rest` counted the warm flag rather than warm children.** `warmUp()` logs and swallows a
   start failure, so a warm server that never came up carries `warm == true` while its process is
   not on the machine. It is `warm && state == .running` now.

The other two were a slice boundary that would not have compiled, and a vouch in
`mock_fidelity.py` that would have turned the build's own row plugs into findings by destroying the
`covered-by-pair` exemption. The first: slice B renamed `ServerRowModel.breaker` while
`ServersBoardRow.swift` still read it — the `Breaker(state: row.breaker)` call, `:46` as `main`
carries that file, which this branch has since replaced.

## Deviations from the plan, and why

1. **`SignalPathGeometry` rather than nine `MetricToken` cases**, against the spec's disposition
   that the literals *"route through `MetricToken`"*. They route through a token layer; which one is
   settled by the doc comment on `DesignDocParser.breakerRows` as `main` carries it
   (`DesignDocParser.swift:327` there; the function is deleted on this branch), which records why
   the breaker's nineteen rows were kept out of the chrome ladder — *"mixing nineteen breaker rows
   into the chrome ladder would bury the four values a window actually lays out with."*
   `MetricToken.jackLane` stays where it is and the geometry reads it, so the lane is authored once
   and a parity test asserts it.
2. **`DesignDocParser.swift` was split.** Adding the Signal Path's reader took it to 410 lines
   against a 400-line limit, so the increased-contrast reader moved to a file of its own. That seam
   was already declared and already argued for in the comment above it. `tableLines` widened from
   `private` to internal as a consequence, which is noted at the declaration.
3. **`StatePlug` sits at `MCPRouterUI/` root rather than under `Boards/`**, where `Breaker.swift`
   sat and for the same reason: `StateContainer.swift` draws it and compiles for both platforms.
4. **The row's leading slot is the plug's width, so the table's columns moved left by 22pt.** That
   is the visible consequence of retiring a 30pt lever rather than an incidental change, and the
   column headers read the same value so the two cannot drift.
5. **AC9 was mis-specified and is recorded as not met.** It asked for the breadth finding count to
   fall; it is 116 before and after. `divergent` is a finding too, so an affordance moving from
   *not built* to *built and measured* trades one finding for another — and no fixture this build
   ships can make a jack's label equal the mock's eleven server names. What moved is the
   composition: `absent` 80 → 75, `divergent` 16 → 21, `covered-by-pair` 16 → 24, `extra` back to
   its pre-existing 10.

## What is open

- **The harness column is not built, and it is the one part of the brief this item does not
  deliver.** Its three states are `HarnessState` in `RouterCore/Discovery/HarnessReconciliation.swift`
  — `notWired(overlapping:)`, `wiredViaHTTP`, `wiredViaShim(bridge:)`,
  `wiredWithDuplicates(route:count:)`, the brief's three exactly — in a target neither app links,
  derived from harness config files. The control API serves no harness route; A36 forbids a board
  going round it. The one thing the app can see, the `client` on a call record, cannot produce *not
  routed* at all, because a harness that has never called cannot appear in a usage log — so the
  state carrying the finding is the state that reading cannot reach. **M22 absorbs `R7-C1` and the
  route**, and the column lands with it. Recorded in `DESIGN.md` §10 and in the pairing file's
  citations. The rail reads hub → jacks meanwhile, which is honest and incomplete rather than
  either alone. *(`spec-M22.md`'s §3 grounding record — `:153` as that file stands at `87e16dc` —
  spells these cases `.wired(route:)`; the source is what is quoted here.)*
- **The band's own paragraph failed A36 before it passed it.** The first draft of `SignalPath`'s doc
  comment spelled out the file-reading APIs while explaining why this view may not use them, and
  that gate is a source grep that cannot tell a mention from a call. The prose is reworded and says
  so. Relaxing the grep to skip comments would put every forbidden call one `//` away from
  invisible — worth someone deciding deliberately rather than the next runner hitting it and
  reaching for the gate.
- **The last jack measures 142.5pt against its siblings' 132.** SwiftUI's `.adaptive` gives the last
  item in a row the remainder of its computed track set, where CSS `auto-fill` would leave empty
  tracks. It is inside the specification rather than outside it — `minmax(132px, 1fr)` allows a
  track to grow, and 132 is documented as a minimum — but it is a divergence from the mock's
  behaviour and is recorded rather than absorbed.
- **The eleven-upstream case is predicted, not measured.** The recorded fixture declares four
  servers, so the packing behaviour at the count the brief actually measured — eleven, which ran the
  band 500pt deep as a single column — is covered by `columns(inJackFieldWidth:)`'s arithmetic and
  by the observed 140pt track pitch, not by a render. A fixture with eleven servers would settle it.
- **`indicator` is unvouched in `mock_fidelity.py`, so 16 mock row-plug affordances still read
  `absent` while the build draws the mark.** The citation on each says why: the harness records no
  text for a dot, so a pairing fails `readable()` on both sides and lands `unclassified` — the
  gate's own phrase for agreement between two absences — and vouching the kind would additionally
  reclassify the build's own plugs as `extra`. It is `D-m23-h`'s subject, the mock kinds
  `VOUCHED_CONTROLS` does not name, and it wants an instrument rather than a table edit.
- **Three branches edit `VOUCHED_CONTROLS` from the same base, and the safe-merge rule is
  mechanical rather than a judgement.** `ai/m19` adds eight roles, this branch adds two, `ai/m22`
  expects to add more. Measured rather than assumed, by parsing the dict out of all three trees and
  taking the union a textual merge produces:

  - **Adding entries can only make more pairings vouched, never fewer.** No already-vouched pairing
    can be un-vouched by another branch's edit, so the whole cross-branch hazard is the *other*
    direction — `MOCK_KINDS_FOR_ROLE` keys on the **build node's role**, and a role gaining a kind
    turns `declared` from 0 to non-zero, which flips that role's unpaired build nodes from
    `covered-by-pair` (silent) to `extra` (a finding).
  - So the check before extending the table is one question: **does the other branch introduce a
    role my surface already uses?** Not *does it touch the same keys* — those are different claims
    and only the second one bites.
  - **It is one check per *surface*, not one per pair of branches, and it includes surfaces that
    edited nothing.** M22 supplied this correction and it is the half that generalises: a branch
    with zero diff on `mock_fidelity.py` has no *conflict*, which is not the same as no *exposure*
    — the quota rule keys on the build node's role, never on who made the edit. Run pairwise across
    all three, `ai/m22`'s harnesses surface carries `callout`, one of M19's eight. Harmless in the
    event, because the only node with that role is paired and the quota rule has nothing unpaired
    to reclassify — but **non-empty**, where a check that inferred stake from the diff had reported
    the hazard closed. *"Came back empty" was this surface, not a property of the merge.* Those are
    M22's numbers over M22's dumps, which this session cannot verify and does not need to: the
    correction stands on the rule rather than on the count.
  - Run for this branch against the union of all three: M19 introduces `badge`, `callout`,
    `codeblock`, `heading`, `list-item`, `sentence`, `tab`, `verified-mark`; the four servers dumps
    carry 39 distinct build roles; the intersection is **empty**, and no role this surface already
    uses gains a kind. Nothing on Servers reclassifies under the merged table, and `unclassified`
    stays at 8. Verified in the other direction by the recovery session: zero occurrences of
    `signature` or `jack` across M19's readme dump — with the stated limit that the readme surface
    has **one** frame where this one has four, so that answer is complete relative to what M19
    measured rather than to the surface.

  **A line number is only a citation in the frame it was written in.** Every reference above names
  its tree, because this item's own note cited `mock_fidelity.py`:808 without one — correct on this
  branch, seventeen lines off on `main`, where it lands in unrelated text about `D-m23-l`. A reader
  following it from `main` finds something plausible and wrong, which is worse than finding nothing.
  The shift was this item's own +18/−1 to that file. Filed by the conductor as **G7**, third
  instance tonight, which is the argument for the remedy being mechanical — quote an anchor the
  reader can grep for and name the tree — rather than a matter of anyone being more careful.

  **An anchor is only better than a line number if the sweep for it normalises wraps**, and this
  file is the case that proves it. Counting the phrase *"agreement between two absences"* in
  `mock_fidelity.py` on `main` gave **four sessions-worth of sweeps four different answers**, and
  none of them is wrong — they answer different questions:

  | Sweep | Answer | What it is actually counting |
  |---|---|---|
  | line-anchored `grep` | **0** | occurrences on one source line. All three are wrapped, so none |
  | `[\s#]+` → space | **2** | `:44-45` (header) and `:284-285` (`readable()`'s docstring) |
  | a different **2** | **2** | `:45` and `:862` — the subset that started the correction chain |
  | per-line scan for `agreement between two` | **1** | `:284` only — `:44` wraps a word earlier |
  | letters-only, then collapse | **3** | all of them: `:44-45`, `:284-285`, `:861-862` |

  **Five sweeps, four answers, one file, one phrase — and the last row is the only complete one.**
  `:861-862` is why: it builds the sentence from two adjacent string literals,

      f"...so nothing was compared{invisible}. Agreement "
      "between two absences is not a measurement"

  so what sits mid-phrase after any whitespace-collapsing normaliser is `Agreement " "between` —
  two quote characters no `[\s#]+` pattern touches. Stripping everything that is not a letter or a
  space finds it. The phrase is in the report the tool emits and in **no contiguous run of its
  source**, which is the shape a sweep has to be built for rather than the shape it usually is.

  That sequence cost one session a false *"the phrase is a paraphrase"*, and cost this one a
  reported count of two before it was checked by reading. **The lesson is not that one normaliser
  is right.** It is that a sweep returning a count nobody cross-checks is a measurement with no
  witness, and that the number only became knowable because two sessions disagreed and went and
  looked. So: cite the anchor **and** the tree **and** the line, because each covers a different way
  the other two fail — and say which question a count answers.

  **The right long-term home for this is `mock_fidelity.py`'s own header**, beside the paragraph
  that already says extending the list is a deliberate, reviewable act — that is where someone about
  to extend it looks, and a progress note is not. It is recorded here instead because this branch is
  finished and a fourth edit to the file three live branches are rewriting would impose a conflict
  on the two still building.

  **The conductor has since filed that header edit as `G8`**, to land as one dedicated change after
  M19, M16 and M22 are all in. This note originally proposed *whichever branch merges last*; the
  ruling rejected that and the reasoning is better than the proposal — M22 has zero diff on the file
  today, so handing it the comment manufactures a conflict surface it does not currently have, and
  "last" is fragile in a way that fails quietly, because merge order can change and a stalled branch
  would strand the rule with nobody holding it. As a post-merge change it costs one commit, has no
  conflict surface, and depends on nobody's timing. **Nothing here is M16's to carry.**
