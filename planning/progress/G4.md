individually, for exactly the reason it demands a skip list of everything else.

## 2 · What was built

| File | What it is |
|---|---|
| `planning/input_accounting.py` | `Tally` — the primitive a reader uses to satisfy the contract. `drop(item, reason)` is shorter than `continue` |
| `planning/reader-accounting.py` | the gate. AST pass; fails on a silent drop, a stale declaration, a moved pin, a malformed row, or a run that resolved no readers at all |
| `planning/reader-accounting.tsv` | 18 declarations, one written reason each, with a pinned row count |
| `planning/null-run-gate.py` | 28 arms against the hermetic assertions, in scratch trees under `mktemp` |
| `planning/ledger-reconcile.py` | `table_ids`, `describes` and `status_rows` converted to the contract |
| `Makefile` | both gates inside `make lint` |

Two detector decisions decided whether this is a gate or noise, and both were reversals of a first
cut that had already shipped a wrong answer about itself:

* **The record must name the dropped item.** A rule accepting "some escaping name was touched"
  accepts a bare `examined += 1` at the top of a loop — a number that moves whether or not the drop
  happened. The first cut accepted it and then reported the gate itself as the one accounting reader
  in the repository, on the strength of a counter two lines above a `continue`.
* **The subject is resolved syntactically, one binding deep.** A general taint pass propagates into
  every container and ends up calling `for state in self.states` a raw-input reader. `ast.walk`
  against `os.walk` is the worked example: the first cut did not distinguish them and read its own
  tree traversal as a filesystem read. Guessing which module a bare name came from is the ambiguous
  binding the Google lane refused for name → quantity, one layer down.

## 6 · Findings, for whoever verifies this

1. **`scripts/lint/no-wire-codable.sh` reports a violation on a clean tree that records zero
   exemptions.** Its last line is `exemptions=$(grep -rn "$EXEMPT_MARKER" … | wc -l | tr -d ' ')`
   under `set -euo pipefail`: with no match, `grep` exits 1, the pipeline inherits it, the
   assignment inherits that, and `set -e` kills the script — *after* printing
   `no-wire-codable: clean`. Exit 1 is its violation code. Confirmed on two identical scratch trees
   differing by one comment line: **exit 1 with no exemption, exit 0 with one.** The real tree
   carries two exemptions today, which is why nothing has hit it. Not fixed — it is R7/P7's gate,
   and G4 asserts it as a known red in the `WIRE-zero-exemptions` arm on P10's principle, so closing
   it turns that arm red on purpose.
2. **A deferred-register row with fewer cells than its header is read by nothing.** Check K drops
   it, check J reads only the other direction, and check H counts it inside a group without naming
   it. 0 such rows in either tracker file today, measured 2026-08-22. Recorded as the accounting
   gate's one `gap`, printed on every run; the fix is another check, not a declaration.
3. **`make test` is 1684 tests in 209 suites here, twice, against the brief's stated main baseline
   of 1686/210.** `git diff HEAD main` is four markdown files with nothing under `app/`, so the
   difference cannot come from this branch. `make lint` likewise reports 530 files where the brief
   says 531. Both predate this item; neither moved during it.
4. **`make all` fails at `parity-selftest`, and did before this item.** Five of
   `parity-manifest-selftest.sh`'s 36 cases report `WRONG REASON`: each one *does* turn the check
   red, but on a different message than the case asserts. It wants `holds 82 rows and pins itself
   at 83`; `planning/parity/surface.tsv` now holds 92 and pins 92, so the pin-mismatch message
   fires ahead of the deletion the case is named for. The pin last moved in `855179b` (R14) and the
   selftest last changed in `6c4829e` (P4), so the expectations have been stale since R14.
   **Reproduced at the base commit `72958de` with identical output**, and G4's diff is eight files,
   none of them `surface.tsv`, `src/index.ts`, `src/router.ts` or the selftest itself. Not fixed —
   it is R4-C/P4's lane. Worth noting that four of the five are themselves G4's shape: a case named
   for a deleted row goes red because a *count* moved, so its red carries no information about the
   deletion.
5. **ORCHESTRATOR.md carries 96 allocation rows for 91 distinct ids.** The new `table row scan`
   denominator line makes the five duplicates visible for the first time; checks H and K both pass
   over them, so they either agree on status or live in tables H cannot read. Not chased.
