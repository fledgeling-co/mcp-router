**N1 equals N2 on this corpus and that is a result, not a redundancy.** No scratch citation is
hidden by a wrap, because a path is a single token and markdown wraps at spaces. What the
wrap-tolerant reader buys is the *marker*: a withdrawal written on the line after its citation is
adjacent here and invisible to a line reader, which is what the control's wrap plant proves.

### The two counts that answer different questions and share a number

At `0e5ff49` the gate found **45 blocking occurrences**, of which **exactly 40 are in files this
branch is permitted to write**. Deduplicated by (file, token) the same set is **41**, of which 36
are writable and 5 are not.

The dispatch brief handed down said *"the tracked count is 40"*, describing **files carrying
absolute paths**. My 40 is **blocking citation occurrences in writable files**. The two agree to
the digit and answer different questions, which is precisely the trap this item exists to name: a
bare integer from an unnamed reader is an assertion wearing a measurement's clothes. For the record,
counting *files* the way that brief did: 44 tracked `.md` hold a `/tmp/` substring, 50 counting
`.json`, 42 restricting to `planning/**/*.md`, 91 over all tracked files. None of those is 40.

### The counts each hole is stated on

counted on every run and blocked on none, and are registered as a follow-up rather than folded in.

the root rather than matching at every depth. An unanchored bare name once swallowed a real source
file in this repository, so the second direction is the one worth running.

this as *tracked in 4 of 12 worktrees*; that counted the worktrees which wrote their own and missed
the one they had all inherited. At `0e5ff49` the file is on **29 branches**, because every branch

deliberately), `9b13a49` (M19, inside a feature commit), `30f639d` (**predating this fleet**).

Settled: `.dispatch/` in the worktree, ignored — inside the repository so a brief can cite a
repo-relative path, outside every item's diff so a `git add` cannot sweep it into a feature commit.
The three bare names are ignored at the root as well, anchored there, because the root is where all
three that landed were written. `WORK-ORDER.md` moved to `planning/dispatch-records/`,
byte-identical, with the explanation beside it rather than inside it.

Moving rather than deleting is the reversible option and keeps `bcc69dd`'s stated intent. Deleting
outright was the alternative and was not taken: history holds the content either way, but a file
nobody can find is not a record.
