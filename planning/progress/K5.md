## The brief's question, answered first

**The control's handler does something.** The sheet's destructive button is
`Button(Self.disableLabel(serverName), role: .destructive)`,
`app/Sources/MCPRouterUI/Boards/ServerSheets.swift:229` at `83e5380`, and its action is
`Task { await board.setDisabled(serverName, to: true) }` — which reaches
`let updated = try await client.patch(server: name, ServerPatch(disabled: disabled))`,
`app/Sources/MCPRouterUI/Boards/ServersBoardWrites.swift:78` at `83e5380`. This is **not** J2's
DEF-062 shape: there is no `Button("Done") { board.sheet = nil }` here, and no arm of the switch
resolves to a no-op.

**Reading the state it was supposed to change through a different channel is where it fails.** The
strike is `PATCH /servers/:name {"disabled": …}`. Following it down one layer, past everything M29
measured, the router-side arm that consumes those bytes is
`set("disabled", (disabled?.isTruthy ?? false) ? disabled : nil)`,
`app/Sources/RouterCore/Control/ControlHandlerPatchFields.swift:67` at `83e5380`.

**Deleting that whole arm left all 688 RouterCore tests in 106 suites passing**, measured on this
branch before any test was written. The file was restored byte-identically — sha256
`397dc468a97b213779ebdc533b68bcd6b3304462e9ca001a6ef20b8ef0680e0c` before and after.

That is M29's own oracle line 6, stated verbatim in its spec:
`PATCH /servers/:name` with `{"disabled": true}` writes the field to `servers.json`, reloads,
`planning/specs/spec-M29.md:264` at `83e5380`.

## Why it was missed, which is the reusable part

M29 wrote **seventeen** DIS arms. Every one of them targets a **reader** of the switch — the tool
union, the reap arm, the hash, the subtitle, the attention band, the sweeps, the row's spoken
value, the sheet's label. Not one targets the **writer**. The three router-side suites that mention
the field — `DisabledSweepTests`, `ControlReindexDisabledTests`, `ConfigParityTests` — each begin
from a fixture that is *already* `"disabled": true`, so they need no write to exist.

A feature whose readers are proved seventeen times and whose single write is proved zero times
reads, from any coverage summary, as thoroughly tested.

## What did cover it, stated so the claim is not overstated

`scripts/acceptance/control-differential.sh` at `d3f17de849579b0942c455edeb972a02aff55b9d` (historical source) **does** drive this PATCH:
`compare_mutating control-server-patch "PATCH disables a server"`,
`scripts/acceptance/control-differential.sh:588` at `83e5380`, with `{"disabled":false}` and
`{"disabled":"yes"}` on the two lines after it. `compare_mutating` diffs the config file as well as
the status and body — `&& [ "$ts_config" = "$swift_config" ]; then`,
`scripts/acceptance/control-differential.sh:560` at `83e5380`.

So the write was **not wholly uncovered**, and this item does not claim it was. Three things that
lane cannot do:

- It is an **equivalence**. It says the two implementations agree, not that either is right. Two
  ports that both stopped writing the member produce identical configs and it stays green.
- It needs a **built binary and a live node reference**, so it is not in `make all`
  (`all: tools lint build test test-ios test-ios-glass parity parity-selftest …`, `Makefile:280`
  at `83e5380`). By this fleet's own rule a lane needing a built binary is `waived`, not `control`.
- It compares **bytes**. It cannot ask the question the user actually has, which is whether a
  session is still served the server's tools.

The gap closed here is: the clause had no witness inside `swift test`.

## What was built

`app/Tests/RouterCoreTests/ControlDisableWriteTests.swift` at `d3f17de849579b0942c455edeb972a02aff55b9d` (historical source), three tests, a fourth member of
`WireGuaranteeTests`' family and separate from it because that file is at its length limit.

**The read-back is deliberately not the response body.** `patch` answers with `Describe.row` of its
own reloaded upstream, so asserting on the response asks the handler whether it thinks it wrote —
the same channel that struck. Every primary assertion reads the user's `servers.json` **off the
filesystem**, re-parses it through `ServerParser`, and puts it to `ToolUnion.isServed`, the
predicate that decides what a session is served.

| Test | Line | What it holds |
|---|---|---|
| `theSwitchReachesTheConfigAndTheServingPredicate` | `:153` | the switch reaches the config and the serving predicate; oracle 6's *reloads* and *response body* clauses stated after the independent channels, not instead of them |
| `enablingRemovesTheMemberRatherThanWritingFalse` | `:195` | a falsy switch removes the member rather than writing `false` |
| `anUnrelatedPatchDoesNotTouchTheSwitch` | `:223` | a warm-only PATCH leaves the switch exactly as it was |

All at `fe9926f`.

**Every test carries a control in the same direction the defect would run.** The untouched sibling
`on` is asserted still served in the first, so a handler that disabled the whole file fails it; the
fixture's starting state is asserted before each write, so no assertion is a restatement of the
seed; and the third asserts `"warm": true` *did* land, so "the switch was left alone" cannot be
satisfied by a request that simply failed.

The second test is the one `isServed` alone cannot reach: a port that assigned the value as given —
the way `idleMs` is assigned four lines above — writes `"disabled": false`, which **is** served, so
only the byte-level assertion bites. The reference is diffed against this file byte for byte.

## Filed, not fixed

**The reference announces a moved tool list on this PATCH and nothing witnesses that arm.**
`if ('disabled' in b || 'projects' in b) {`, `src/control.ts:698` at `83e5380`, whose body is
`announceTools(deps, \`changed what "${name}" serves\`);` on the line below it. `scripts/e2e-live-reload.mjs` drives an add, a **warm-only** PATCH as the negative
control, and a delete — `const patched = await post('/servers/second', { warm: true }, 'PATCH')`,
`scripts/e2e-live-reload.mjs:177` at `83e5380` — and never a disable. So *disabling a server tells
every attached session its tool list moved* is unmeasured, on the router that ships.

Not fixed here for two reasons, both checkable rather than preferential: `spec-M29.md` never claims
it — the string `announce` does not appear in that file at `83e5380` — so it is R29's clause rather
than M29's; and the Swift port has **no live-reload subsystem at all** (`announceTools`,
`list_changed` and `listChanged` return zero hits across `app/Sources/` at `83e5380`), which makes
it a port-gap question about a whole subsystem rather than a missing assertion about this switch.
Owed as a row against R29, not against M29.
