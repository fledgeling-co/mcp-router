# The citation gate landed and immediately found forty-two unfalsifiable claims

- origin: the citation gate's first run on the integration branch after two merges · 2026-08-26
- audience: Whoever maintains the project's written records
- platforms: n/a
- proposed-by-ai: false

## What and why
The gate that checks whether a record's pointers can still be followed has now run on the main line
for the first time, and it reports that six files hold more unfollowable references than the
baseline permits — forty-two more in total. Nothing it found is false: no reference points at the
wrong thing. They simply carry no way for a reader to check them, which is what the gate calls
unfalsifiable and what it exists to stop accumulating.

Roughly thirty arrived with a feature merged the same day, in documents written before the gate
existed. Nine are in a file with uncommitted edits made outside this work. Three were written by
the orchestration record itself, after the rule was known — which is the part worth taking
seriously, because a discipline the record-keeper does not follow will not survive contact with
anyone else.

The gate is a ratchet whose own rule is that a file's count may only fall. Raising the baseline to
absorb this would keep the main line green and remove the gate's meaning on the day it arrived, so
the debt is recorded as work instead. The cost of leaving it: the main line's checks stay red until
this is paid down, and a check that is permanently red stops telling anyone anything — the same
failure this project has already recorded twice elsewhere.

## Acceptance sketch
- The six named files carry references a reader can follow, or the references are removed.
- The main line's checks pass again without the baseline having been raised.
- New records written after this point do not add unfollowable references.
- The gate's count falls rather than being absorbed, and the fall is visible run to run.

## Assumptions made writing this
- Assuming the debt is paid down rather than absorbed by a higher baseline, since the gate's own
  stated rule is that counts may only fall.
- Assuming the references written by the orchestration record are fixed first, on the ground that a
  rule its own author does not keep will not be kept by anyone else.
- Assuming the file with uncommitted outside edits is left alone until whoever is editing it lands
  their work.
