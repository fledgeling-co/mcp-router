## What this item is really for

The TypeScript router in `src/` keeps running and stays the installed default. Nothing here
changes the user's setup. What R1 buys is what R4's parity gate needs in order to exist: a Swift
implementation whose observable outputs can be **compared against the TypeScript one,
mechanically, on the same inputs**.

That sets the bar. A port that is merely *plausible* is worthless to R4 — the gate compares two
routers, and a difference it cannot explain is a difference it must treat as a regression. So the
criteria below are dominated by **differential parity against the real TypeScript implementation**,
driven from `dist/` (verified drivable: `dist/config.js` and `dist/manifest.js` both export their
full surface, and `upstreamHash` on a real fixture returns `62b266dd2467e747`). The vectors that
comparison produces are committed; the `dist/` build that generates them is not.

**Parity is the default, and every departure from it is enumerated.** The register in
*Declared divergences* below is the complete list of places Swift intentionally behaves
differently. Anything not in that register must match, including the parts of the TypeScript
behaviour that are accidents of JavaScript rather than decisions. Those are the expensive ones,
because they are invisible to anyone porting from the source's intent rather than its behaviour —
so they are enumerated too, in *Preserved JavaScript semantics*.

## Acceptance criteria

The oracle for every later stage. Each clause is independently verifiable; evidence must be a
measurement, an exercised command, or a red-green test — never "it looks right".

Where a clause says **differential**, its evidence is a comparison against output generated by
running the TypeScript implementation on the same input, not an expectation typed by hand.

### The two named traps

| # | Clause | Evidence type |
|---|---|---|
| A1 | A `servers.json` whose top level is a **flat map of server names** — the recorded trap — fails with a named, actionable error naming the file and the fix. It never loads zero servers quietly | red-green test on the trap fixture |
| A2 | The four outcomes are **distinguishable at the type level**: file absent · not valid JSON · valid JSON whose shape is unrecognised · a valid config that genuinely declares no servers. A caller renders these differently because the values differ, not because it guessed | type-level assertion + a test asserting four distinct cases |
| A3 | **No decode path in this item has emptiness as its failure mode.** Specifically: a `mcpServers` that is present but is not an object (`"bad"`, `[]`, `null`, `7`) is an error, **not** an empty config — the defect the trap fixture alone does not catch, because a decoder can special-case that one fixture and still default everything else to empty | red-green test per non-object type, plus a diff assertion that no `catch`/`try?` in the item yields an empty collection |
| A4 | Both TOML client-config key shapes parse: `[mcp_servers.docker-mcp]` (Codex CLI) **and** `[mcpServers."docker-mcp"]` (ChatGPT CLI), from fixtures transcribed from the two real dAIolog configs. A file carrying **both** tables is resolved by a stated rule, not by whichever the parser reached first | red-green test, three fixtures |
| A5 | A TOML client config carrying **neither** key shape is reported as "declares no MCP servers", distinct from a parse failure and from an absent file | test asserting three distinct outcomes |
| A6 | Discovery covers all six named clients with their real paths, returns them in a **stated deterministic order**, reports an absent config as a normal *absent* result rather than an error, and filters the router's own entry out of what it reports | table test over a fixture home directory |

### Manifest — `src/manifest.ts` parity

| # | Clause | Evidence type |
|---|---|---|
| A17 | `toolsDigest` matches the TypeScript digest, and matches its **material rule**: only `name`, description (nullish → `""`) and `inputSchema` (nullish → `{}`) are hashed; every other tool member is ignored; **schema member order is significant**; tools sort by name only, so two tools with the **same name** keep arrival order and reversing them can change the digest | differential test incl. the duplicate-name and schema-reorder vectors |
| A18 | A cached tool **round-trips losslessly, member order included** — unmodeled fields survive a decode/encode cycle, so what is served to clients is what the server advertised. The check exercises the **modified** path too: change only `builtAt`, save, and the unmodeled fields are still present | byte comparison after a *modifying* save, not only an unchanged one |
| A19 | Re-serialising a manifest produces the bytes the **TypeScript serializer** would produce for the same value — two-space indent, no trailing newline, its property ordering — rather than the bytes of the input file, which is a weaker and different claim | differential test against `dist/manifest.js` output |
| A20 | The manifest parser is **as shallow as the reference**: `servers: []` is accepted, cached-server entries are not validated, and unknown fields are preserved. A stricter Swift parser would be a divergence and is not wanted here | differential test naming the `servers: []` vector |
| A21 | `diffTools` matches: it inspects only the **new description of added and changed tools** — not names, schemas, old descriptions or removed descriptions — dedupes codepoints by first occurrence, emits added/changed in `after` order then removals in `before` order, and omits the old schema on a removal | differential test |
| A22 | The invisible-codepoint detector covers **exactly** the reference's ranges and reports `U+XXXX`. `U+2066` is **not** among them and must not be reported — a more thorough detector is a divergence | red-green test incl. a planted zero-width character and a `U+2066` negative case |
| A23 | `saveManifest` is atomic (temp `<path>.tmp-<pid>` + rename), creates the directory, overwrites on rename, and its behaviour when the write fails — including whether the temp file survives — is specified and tested | test + an interrupted-write test |
| A24 | `ManifestStore` matches on all four paths, not just the happy one: re-reads only when mtime **or** size moved; a failed reload keeps the previous manifest, backs off **one second**, and does not record the stamp; a **malformed file at construction** records its stamp and therefore does not retry until the file changes; a **deleted** file leaves the previous manifest and does not clear the stamp | differential test per path, incl. an assertion that the back-off is one second and not merely "some window" |
| A25 | `isStale` matches on its **false** cases as well as its true ones: an entry with a matching hash but a missing digest, empty tools, a pending surface, or `error: ""` is **current** | differential test on all four |
| A26 | The in-scope `buildManifest` bookkeeping matches: first sight auto-approves; an equal digest replaces the entry and clears error and pending; a changed digest keeps the approved tools, digest and `builtAt` while replacing pending and updating the config hash; **a failure overwrites approved tools with an empty list** (N8); removed upstreams stay in the manifest; `force` bypasses staleness; and the input manifest is mutated in place | differential test per branch, incl. the destructive-failure vector |
| A27 | `unionTools` matches: it skips an entry whose approved tools are empty **before** any placard is applied — so the error placard is unreachable through the normal failure path (N8) — a declared placard outranks an entry error, an empty description falls back to the tool name, and every other tool member survives the copy | differential test, incl. the unreachable-placard vector |
| A28 | `visibleTo` is a **lexical, case-sensitive string test**, not path normalisation: a project `/a/b/` matches cwd `/a/b/c`; `/a/b` does not match `/a/bc`; `projects: [""]` matches every absolute cwd; `..`, doubled separators and symlinks are **not** normalised | differential test naming all five |
| A29 | `splitToolName` splits at the **first** separator, so `a__b__c` is server `a`, tool `b__c`, and `a____b` is tool `__b` | differential test naming both |

## Declared divergences from the TypeScript reference

The complete list of places Swift intentionally behaves differently. **R4's gate consumes this
register as its expected-difference rules**; a difference not listed here is a regression.

| # | Divergence | Why | What R4 does with it |
|---|---|---|---|
| D1 | A `servers.json` with no recognisable `mcpServers` object — or one that is present but not an object — is an **error**. The reference loads zero servers silently | The brief mandates it. A silent empty result is indistinguishable from "you have no servers", which is the worst failure available to a surface that renders both | Expected divergence. Feed the trap fixture; TS returning empty and Swift erroring is a **pass**, and the two agreeing would be the failure |
| D2 | `loadManifest` reports *that it degraded and why* in its return value. The reference returns an ordinary empty manifest and says so only in a log line | A caller cannot distinguish "cache is cold" from "cache is corrupt" if the value is the same. This is the one place emptiness survives as a recovery, so it is the one place it must be labelled | Not observable in the manifest file. Compare the resulting manifest only |
| D3 | The `servers.json` writer is **atomic** and **preserves top-level keys it did not set**. The reference's writer (in `src/index.ts`, not in the three ported modules) writes four keys non-atomically | A truncated write produces exactly the unrecognisable shape D1 exists to reject. Dropping `startupTimeoutMs` on a rewrite silently resets a supported setting | Compare the four keys the reference writes; extra preserved keys are expected. Note this writer is **adopted from `src/index.ts`**, so it is not a port of the three named modules |
| D4 | A directory-creation or stderr-write failure in logging is **contained**. The reference catches only the append, so those two propagate and can take the router down | "Logging must never take the router down" is the reference's stated intent; its code does not achieve it. Swift implements the intent | Not observable. Log bytes are compared, not failure modes |
| D5 | The log API takes a structured event. There is no call that accepts a whole config, env dictionary or header dictionary. The reference's methods take an unrestricted string | A token reaching a log file is not recoverable after the fact. Enforced by the type rather than by care | Not observable. Emitted bytes are identical (A30) |

## Preserved JavaScript semantics

Behaviour that is an artefact of JavaScript rather than a decision, and is **kept anyway** because
parity is what R4 measures. Each is a way a careful Swift port silently diverges while looking
correct, so each has a named vector in the corpus (A40).

| # | Behaviour | The vector that catches it |
|---|---|---|
| N1 | Env/header keys sort by **UTF-16 code unit**, not Unicode scalar | Keys `"\u{1F600}"` and `"\u{E000}"`: the emoji sorts **first** in JS (lead unit `D83D` < `E000`) and **last** under Swift's default `<` |
| N2 | `args` order is **significant** and never sorted | `args: ["z","a"]` must not hash as `["a","z"]` |
| N3 | Option precedence is **nullish** (`??`), not truthy | `port: 0`, `host: ""`, `idleMs: 0` are honoured, not replaced |
| N4 | `splitToolName` splits at the **first** separator | `a__b__c` → server `a`, tool `b__c` |
| N5 | `visibleTo` is lexical and trailing-slash-aware | project `/a/b/` vs cwd `/a/b/c`; and `projects: [""]` matching everything |
| N6 | `toolsDigest` sorts by name only and is **stable**, so equal-named tools keep arrival order | Two tools named `x` with different descriptions, in both orders |
| N7 | Schema **member order** changes the digest | `{"z":0,"a":1}` vs `{"a":1,"z":0}` |
| N8 | An indexing failure **erases the approved tools**, which makes the error placard unreachable through `unionTools` | A server with approved tools, then one failure — the tools are destroyed. **This is a defect in the reference**; it is ported faithfully and reported as a deferred child, because fixing it here would break the parity gate that has to run first |
| N9 | `isSelfReference` compares the port **as the URL reports it**, so a default port reads as empty and never matches | `http://localhost:80` against port 80 → false |
| N10 | Skipped entries follow JS property enumeration order — integer-like keys first, ascending | Keys `"10"`, `"2"`, `"a"` → order `2`, `10`, `a` |
| N11 | The invisible-codepoint detector covers only its hard-coded ranges | `U+2066` is **not** reported; `U+200B` is |
| N12 | A URL is validated for parseability, not scheme | `ftp://host` under `type: "http"` is accepted |
| N13 | `isHttp` is true for every non-stdio transport | `sse` → true |

## Design representation — 2026-08-14

**R1 renders nothing.** It is a library: no view, no surface, no interaction, no overlay.
Inventing screens for it would be fabrication. The honest scaling of the design stage is to cover
what this item genuinely owns — **the words** (`DESIGN.md` §6), and the *data* later surfaces need
in order to tell §5's states apart.

That is not a formality. The recorded trap is a design failure in engineering costume: a flat
`servers.json` renders as **Empty** ("you have no servers") when the truth is **Error** ("this file
is a shape I don't understand"). No care in M3's view layer recovers a distinction the value it was
handed has already thrown away. A2 is the criterion that makes the distinction survive the
boundary, and A3 is the one that stops it being special-cased to a single fixture.

### Which `DESIGN.md` §5 states this item feeds

| State | What R1 supplies | Surfaced by |
|---|---|---|
| Empty | a config that parsed and genuinely declares no servers — a *distinct value*, not an empty list that could equally mean failure | M3 |
| Partial | the skipped-server list: each name with the reason it could not be adopted | M3 |
| Error | typed load failures, each carrying the file path and the fix | M3, M8 |
| Offline | — not this item; "the router is not running" belongs to the control client | F3 |
| Default · Loading · Success · Disabled · Overflow | — not this item; no surface | — |

### The copy, written now rather than left to a later runner

Sentence case, states what happened and what to do, names the file, blames nothing, does not emote.

| Condition | Copy |
|---|---|
| No config file | `No server list at ~/.claude/mcp-router/servers.json. Run `mcp-router import` to generate one from ~/.claude.json.` |
| Flat `servers.json` (the trap) | `~/.claude/mcp-router/servers.json has no "mcpServers" object. The servers look like they are at the top level — wrap them in "mcpServers": { … }. Nothing was loaded.` |
| `mcpServers` present but not an object | `~/.claude/mcp-router/servers.json has an "mcpServers" that is a <kind>, not an object of servers. Nothing was loaded.` |
| Config unparseable | `~/.claude/mcp-router/servers.json is not valid JSON (<reason>). Nothing was loaded.` |
| Skipped: bad name | `name is not [A-Za-z0-9_-]+, so it cannot be a tool namespace` |
| Skipped: `__` in name | `name contains "__", which is the tool namespace separator` |
| Skipped: no command | `stdio server has no command` |
| Skipped: no url | `<type> server has no url` |
| Skipped: bad url | `url is not parseable: <url>` |
| Skipped: unknown transport | `unsupported transport "<type>"` |
| Manifest unreadable | `manifest at <path> unreadable (<reason>); rebuilding` |
| Manifest reload failed | `manifest reload failed (<reason>); serving the previous one` |
| TOML with neither key shape | `<path> declares no MCP servers under "mcp_servers" or "mcpServers".` |

The six *skipped* strings and the two *manifest* strings are carried over **verbatim** — they are
already the reason text a user sees, and rewording them would make R4's gate report a difference
that is only a rewording. The first line's "generate one" is likewise the reference's word, not a
paraphrase. Improving any of them is a real item, and it belongs to the surface that first renders
them.

**Codex cross-family spec review — 2026-08-14**

Reviewer: `gpt-5.6-sol`, read-only, `max` effort — `/tmp/gate-R1-spec.md`.
**Verdict: MATERIAL DEFECTS — 44 findings. All accepted; the spec above is the rewrite.**

*Lane note, recorded rather than hidden:* the review ran to completion at `max` (19,979 bytes,
44 findings) but its **wire header was not captured** — the command's stdout was tailed and the
header is printed at the head. A probe with the identical flags from the identical working
directory returned `model: gpt-5.6-sol` / `reasoning effort: max`, which is the evidence that the
invocation form is honoured here; it is not a header from the review run itself. Subsequent gates
capture the full stdout.

The review's central objection reshaped the whole document: **the first draft claimed differential
parity with the TypeScript router and separately specified five deliberate divergences from it,
without ever reconciling the two.** Several clauses therefore asserted parity while requiring
different behaviour — A14 claimed a byte-identical read/write cycle the reference does not perform,
A16 called the reference's parser "strict" when it accepts `servers: []`, A17 required a
degradation report the reference does not produce, A20 described placard behaviour the reference's
own failure path makes unreachable, and A25 credited the reference with never letting logging take
the router down, which its code does not achieve. The fix is the **Declared divergences** register
plus **Preserved JavaScript semantics**: parity is the default, every departure is enumerated, and
R4 consumes the register as its expected-difference rules.

The second theme was that **finite golden vectors do not establish behaviour over a domain**. The
reviewer supplied concrete implementations that pass every named fixture and are still wrong —
sorting map keys by Unicode scalar (passes all ASCII vectors, inverts `U+1F600` against `U+E000`),

The first round found the plan's JSON foundation **architecturally wrong rather than incomplete**,

> Swift's `String` cannot represent a lone UTF-16 surrogate, and it compares by **canonical
> equivalence**. So `{"é":1,"é":2}` is two distinct keys in JavaScript and **one** key in
> Swift.

Storing JSON strings as `String` would therefore have merged two keys the reference keeps apart,
changing the bytes the digest is taken over — silently, on a value no ASCII fixture would ever
expose. The storage type is now `JSString`, a `[UInt16]` wrapper with code-unit equality and
ordering. Nothing else in the port would have caught this: every hand-written fixture in the
corpus is ASCII, and the reference and the port would have agreed on all of them.
