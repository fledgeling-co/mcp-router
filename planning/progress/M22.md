  fourth as new modelling; the type's own doc comment already names the brief. What that

  rows appear and the count goes seven to nine; a regroup is a different change.
  `Destination.swift`'s comment anticipating it is answered here rather than acted on.

  owner on 2026-08-16. The census had already outgrown it — 92 rows less 1 standing exclusion
  derived 91 before this change, 93 after — and `parity-gate.sh` says in its own words that a
  drift there needs an owner rather than a script. **This is the one number on the item that
  wants an owner's eye.**

## Fidelity — where the M23 gate actually stands

`harnesses`: **`tokens`, `literals`, `structure`, `geometry` and `type-metrics` clean** over 193
nodes across four states. `copy` 1 finding. `breadth` 141: 88 extras **all cited**, 10 absences
under the manifest's declared divergences, and **42 `unclassified`**.

The 42 are M23's own registered `D-m23-h`, not a defect in this surface. `VOUCHED_CONTROLS` in
`mock_fidelity.py` covers the six mock kinds the one filled ledger paired, and its comment says
so: *"the first surface to pair one reads it as a finding until the pairing is vouched"*. This is
the first surface to pair `banner`, `indicator`, `callout`, `section-header` and the row actions.
Extending that table is described there as a deliberate, reviewable act; **it has not been done
here**, and the layer manifest's §7 carries the split, measured off the run's own ledger:

- **10 of the 42 would measure nothing if vouched.** Both sides carry no text, so the engine's
  `present if mock_text == app_text` fires on two empty strings — agreement between two
  absences, which is the defect `VOUCHED_CONTROLS` exists to stop and which its own header names
  in those words. Vouching any of them buys a green row establishing nothing.
- **32 would measure something.** Both sides carry text, and the table is where those pairings
  would be recorded.
- **One of the ten is not about the table at all**: `icon <- state-illustration` is already
  vouched at `mock_fidelity.py:68` and still reads unclassified, so its cause is the
  comparable-granularity gate. The open question had two causes in it and only one is the table.

**The table is also moving.** M16 has `scripts/acceptance/mock_fidelity.py` at +18/−1 on `ai/m16`
from this same `87e16dc` base — adding `signature` to `card`, adding a `jack` entry, and leaving
`indicator` deliberately absent for the same reason the first bucket above gives. This branch's
copy has **zero diff against main**, verified. Two items editing one dict from one base is a merge
conflict in the file whose job is to be the oracle, so this is **a sequencing question for the
owner, not something to resolve on either branch alone.**

**One defect of mine that this analysis surfaced**, now fixed: the loading frame's two mock cards
were paired against skeleton cards, which is the pairing `VOUCHED_CONTROLS` refuses by name

## Merge-time obligations — read before merging with `ai/m18`

Established with M18's session on 2026-08-22, against `ai/m18` at `6721e5c`. **None of this is
compiled against on this branch**, because `app/Sources/MCPRouterKit/Shell/RouterSheet.swift`
does not exist here.

- **`RouterSheet.Kind.reconcile` carries `owner: "M22"`, and that is a record of a deliberate
  hole rather than a slot to fill.** `RouterSheetTests.unhostedKindsAreTheOnesOnRecord` asserts
  `.reconcile`, `.readme`, `.recommendation` and `.analyzer` stay in the *unhosted* set. Hosting
  one removes it from that set, forces its owner to nil, and reddens two tests **on `ai/m18`**.
  So this board hosts no reconcile sheet and `HarnessesBoardModel.Sheet` carries no case for one:
  the two controls that would open it are drawn dim with their reason, per §3.4. An earlier draft
  had an unreachable `.reconcile` case and a `HarnessSheetHost` arm that dismissed it; both are
  removed, because an unreachable case reads as an intention to host.
  *(The first note from that session said the opposite — that the cases were slots to line up
  with. It was corrected before anything was built on it. Recorded so the next reader does not
  re-derive the wrong reading from the case names.)*
- **The shim explanation sheet stays local, and the mock has no id for it.** The mock's complete
  `sh-*` set is 13 ids and none matches `/shim/i`. M18's `Kind` has 16 cases: the three extra
  carry a **leading hyphen** in their raw value (`-registry-detail`, `-reset-history`,
  `-skill-provenance`), which is how an app-side sheet with no mock counterpart is registered
  without claiming an id it does not have. Whether the shim explanation should take one is M18's
  call on M18's file; the option is recorded so the conversation starts from three rather than two.
- **The disabled-primary collision cannot arise on either board, and §3.4 is the reason rather
  than care.** `design/mcp-router-console.html:679-680` puts `.btn:disabled` and `.btn.primary`
  at the same specificity with `.primary` declared second, so the mock cannot express a disabled
  primary at all — it keeps its accent fill and `--on-accent` label. Measured independently by
  two sessions. Every disabled control on these boards is a `StandardButtonStyle` **by
  construction**, because §3.4 allows one prominent accent-filled action per view.
